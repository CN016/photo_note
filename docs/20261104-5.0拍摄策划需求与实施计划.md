# 5.0 拍摄策划需求与实施计划

## 目标与现状

在现有拍摄策划的版本化富文本文档上增加拍摄信息、执行状态、档期联动、人工总结、独立总结文档、AI 分析及作品集关联。现有编辑器已支持任务清单、删除线、灵感图及本地图片导入；策划保存以 revision 防止覆盖并发修改；档期具有单次及重复事件，作品集已有策划关联。既有图片分析模型不能视为文本大模型。

本文是实施计划，除已明确标注的现有能力外，以下均为待实现功能。

## 已确认产品规则

- 策划记录拍摄开始、结束时间、地点、人物称呼及照片或视频类型。策划列表按未完成、已执行、已完成分组，同时显示文字和灰、红、绿色，状态由服务端计算。
- 没有勾选或任务项删除线时为未完成；存在勾选或任务项内非空文字的删除线、但人工总结没有非空文字时为已执行；存在执行标记且总结有非空文字时为已完成。普通正文删除线不参与计算。取消标记或清空总结后重新计算。
- 拍摄信息完整后查找当前用户和空间的候选档期；用户确认已有候选，否则创建单次档期。仅同步本策划创建的档期，不能自动修改用户选择关联的已有档期。失败不丢失策划，提供重试。
- 人工总结保存在策划中；明确点击完成总结后，创建一份独立文档，默认名称包含时间、地点、人物和类型。每个策划最多创建一份；副本与策划总结之后独立编辑。汇总页支持检索及打开文档。
- AI 由管理员配置外部文本服务和模型，用户主动触发生成；只发送所需文本，结果单独保存并可编辑，重生成不能静默覆盖用户编辑。服务未配置或失败时允许重试，不改变人工总结和状态。
- 沿用灵感库和手机图库导入，策划与当前用户、空间内的作品集双向关联。

## 技术设计与实施顺序

1. 设计增量迁移及 API：策划拍摄信息、人工总结、状态及关联应与现有 revision 一起维护；旧客户端省略新字段时必须保留其原值，不能覆盖新数据。列表按状态在服务端分页或分组，不能只对单页数据分组后宣称是完整分类。历史正文需兼容，状态由历史任务清单安全回填。新增表和关联均遵守组织及用户隔离、业务 UUID、中文字段注释及无外键约束。
2. 实现服务端动作识别，限定任务项内的勾选和删除线；以实际 JSON 节点层级处理嵌套任务，避免正文格式误判。人工总结及正文在同一修订事务中计算状态，拒绝并发旧版本覆盖。
3. 实现档期候选、关联及创建。候选匹配应对同一空间和用户的时间、地点、人物进行精确比较；既有档期未有结构化地点、人物字段时，不能猜测文本含义，需采用可验证的结构化来源或要求用户选择。记录创建来源和关联，事务、重试和并发必须幂等；编辑或删除策划不得误删已有档期。
4. 实现总结文档及汇总页。复制动作应以当前已保存的总结为准，在服务端保障并发幂等，文档和策划后续独立保存；明确删除策划与副本的生命周期并保护用户数据。
5. 复用作品集与策划关联，增加策划侧选择和双向跳转，服务端重新验证两端归属。
6. 接入文本 AI：模型地址、名称和密钥由统一配置服务读取并保持私有；服务端限定可访问地址、超时与请求体大小，日志不记录密钥及用户内容。输入来源、覆盖确认、失败重试、空间切换与迟到响应均须明确处理。
7. 页面延续现有摄影选片台：中性界面承托图片，保留蓝色品牌，操作按钮明确，状态文字配合颜色。使用 Element Plus 图标；移动端保持可触控、可阅读和无横向溢出；所有可见文案同步中英文。

## 验收与交付

覆盖状态切换及回退、嵌套任务、普通删除线、旧文档及并发保存；档期候选、重复创建、修改及重试；总结副本幂等和独立编辑；AI 未配置、失败、并发与重生成；作品集双向关联。隔离测试覆盖个人、两个组织、同组织不同用户、跨空间关联和缺失范围。数据库迁移须在独立 PostgreSQL 测试库验证，不能用生产库清理数据。

按实际变更运行前后端测试、类型检查和构建，检查中英文键及桌面／移动布局；Android、PC、iOS、小程序的真机或平台检查分别记录，未执行即标注未验证。按项目规范递增后端版本、编写改动记录、按逻辑单元提交，并为受影响平台构建对应交付包；构建、签名、部署和线上验收分别记录。
