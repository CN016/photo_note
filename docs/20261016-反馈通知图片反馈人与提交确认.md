# 反馈通知图片、反馈人与提交确认

## 改动目的

让管理员从 webhook 消息中识别反馈人并打开反馈图片；让提交成功后的用户看到明确的感谢与等待提示；同时让消息中心清楚显示 webhook 的状态、失败分类和尝试次数。

## 主要变更

- 反馈 webhook Markdown 增加反馈人昵称和手机号；游客标记为未登录。账户已不存在时仍发送通知并显示安全占位文案。
- 企业微信和钉钉反馈消息保留图片 Markdown，并附加可点击图片 URL。飞书卡片只发送可点击图片 URL；现有配置只有飞书自定义机器人 webhook，无法取得上传图片所需的 `image_key`。
- 消息中心分别显示投递状态、HTTP 状态码或安全错误分类，以及等待重试/最终失败任务的尝试次数。
- 反馈提交成功后清空文字、释放本地图片预览并重建上传组件，表单面板改为感谢和耐心等待提示。
- 后端版本从 `2.3.3` 升至 `2.3.4`，未新增数据库结构。

## 验证

- `gofmt` 已应用于改动的 Go 文件。
- `go build ./...`：通过。
- `npm run build`：第一次运行在生成 `components.d.ts` 时遇到文件打开错误，单独重跑后通过；Vite 提示现有较大 bundle chunk 警告。
- 中英文消息中心与反馈文案的键集合检查：通过。
- 未运行测试；未连接线上数据库或实际飞书 webhook。

## 未验证与限制

- 用户提供的线上截图中，一条旧反馈显示 `delivered`，更新的图片反馈显示 `retry`。之前的错误记录包含 `notice_worker_claim_failed` 与 PostgreSQL SQLSTATE `0A000`；现有错误日志只保存安全结构字段，无法从这些记录确认数据库拒绝的具体语句。此处没有线上数据库连接，不能确认具体生产故障原因或消息最终是否到达群聊。
- 飞书自定义机器人卡片的图片组件需要上传图片得到 `image_key`；当前 webhook-only 配置不包含这项能力，因此向卡片提供可点击的公开图片链接。参见[飞书自定义机器人官方指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。
