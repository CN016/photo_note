# 编辑器架构规范补充

## 改动目的

结合跨平台图片与文本编辑软件的技术方案，补充 Web 核心、平台壳、编辑文档、性能验证和平台构建方面的项目规范。

## 主要内容

- 明确 Web 应用是编辑界面和业务交互的主要实现；桌面和移动端壳提供系统能力，不复制编辑规则。
- 规定微信小程序单独验证承载方式和平台桥接；`web-view` 是候选方案，具体覆盖范围以真机验证为准。
- 补充编辑器模块边界、可版本迁移的 JSON 文档格式、二进制资源分离和撤销重做要求。
- 补充大图、像素处理、移动端内存及导出性能原则，以及框架锁定前的原型验证范围。
- 明确 Apple 平台构建、签名和发布需在 macOS/Xcode 环境验证；发布密钥应放在 CI 安全存储中。

## 技术选择边界

参考方案提出了 React、TypeScript、Vite、Konva、Tauri 2 和 Capacitor 等候选技术。本次将其架构原则写入规范，没有把具体框架或库定为强制项；需先通过项目原型验证性能、平台能力和构建流程，再记录正式选型。方案原先覆盖 Windows、macOS、iOS、Android 和未来 Web，项目当前还包含微信小程序，因此规范额外加入了小程序承载与适配要求。
