# 开发规范组织隔离补充与评审

## 改动目的

落实新增表默认包含 orgid 的要求，并结合当前多租户实现修正规范中的过时描述，避免后续开发绕过组织或用户授权。

## 评审发现与调整

1. **新增表缺少组织隔离要求**：旧通用字段列表未包含 orgid，且未要求登记隔离回调。现要求非空 bigint、有效编号约束，并同步模型、managedTenantTables、启动检查、组合索引和隔离测试；例外必须说明原因与替代隔离方式。
2. **文件授权条款已过时**：旧文档要求不绑定用户，与 FileService 和 file_ownerships 的实际边界冲突。已明确私有文件按组织及用户授权，并保留头像与既有公开业务的独立范围。
3. **配置表名称错误**：实际表名为 app_configs，模型和迁移均已固定。修正名称，并说明当前系统配置固定 -1 域。
4. **技术栈待定描述与实现冲突**：顶层目录说明仍写后端技术栈待决定，已改为沿用现有 Go/Gin/GORM/PostgreSQL/Redis。
5. **隔离规则仅靠字段不足**：补充可信上下文、组织内创建者权限、原始 SQL 和关联校验、异步任务范围、缓存与幂等键、空间切换边界；全局扫描处理单条数据前必须收窄范围。
6. **测试通过易与数据库验证混淆**：明确独立测试库和 PHOTO_NINI_TENANT_TEST_DSN，以及跳过集成测试时的报告要求。
7. **扩展 JSON 的功能边界缺失**：按当前用户偏好实现补充功能命名对象和局部更新保留其他键的规范。
8. **迁移执行方式不够明确**：补充当前启动仅检查结构、不自动执行迁移的事实，以及先备份并依序执行迁移再启动新版本的要求。

## 核对依据

- `backend/internal/model/models.go`：BaseModel、AppConfig、User。
- `backend/internal/store/tenant_scope.go`：受管表登记、GORM 隔离回调、系统上下文与原始 SQL 边界。
- `backend/internal/tenant/context.go`：个人域、可信 Scope、系统权限及范围收窄。
- `backend/internal/service/files.go`、`backend/internal/database/postgres.go` 与迁移 000021：文件授权、启动检查和 orgid 约束。
- `docs/multitenancy-api-v1.md`：组织内创建者权限、文件与公开业务边界、升级规则。
