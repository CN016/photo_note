# Docker 镜像双标签导出修复

## 改动目的

修复 v2.7.0 导出包只含版本标签、而 Compose 仍引用 `photo-nini-api:local`，导致服务器启动时未使用新镜像的问题。

## 主要改动

- 将 v2.7.0 镜像的 `photo-nini-api:local` 标签指向同一镜像，并重新导出同时含 `photo-nini-api:2.7.0` 与 `photo-nini-api:local` 的归档。
- 更新后端 README 的构建、导出和启动流程，要求导出两个标签，并在服务器导入后强制重建 API 容器。
- 当前服务器可立即执行：`docker tag photo-nini-api:2.7.0 photo-nini-api:local`，随后运行 `docker compose up -d --no-build --force-recreate api`。该命令适用于当前目录为 `backend` 的情况。

## 验证

- 已检查两个标签指向相同的 `linux/amd64` 镜像后生成多标签归档，并重新计算 SHA-256 校验文件。
- 已执行 `docker load` 验证归档可加载且两个标签均存在；加载后再次检查两个标签指向同一个 `linux/amd64` 镜像。
- `git diff --check`：通过。

## 未验证内容与限制

- 未连接用户服务器执行容器重建；服务器侧需在 `backend` 目录按上述命令操作。
- 本次只修正镜像导出标签和部署说明，不涉及后端代码或 API 版本变更。
