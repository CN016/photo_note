# Go 后端 V1 实现

## 改动目的

按 `docs/backend-design-v1.md` 将 Go、Gin、GORM、PostgreSQL 和 Redis 后端从设计补充为可构建、可通过 Compose 启动的 V1 服务。

## 主要内容

- 新增 Go 服务入口、环境配置、Argon2id 密码处理、PostgreSQL repository、Redis access/refresh token 管理和 Gin API 路由。
- 实现注册、登录、刷新、退出、当前用户资料、标签 CRUD、灵感图 CRUD 与分页/标签检索；除注册、登录和刷新外的全部接口（包含退出与 `/healthz`）校验 Redis 中的 Access Token。
- HTTP 监听、请求上限、服务超时及 token 有效期通过统一配置服务从 `app_configs` 读取，新增 `000002_seed_runtime_config.sql` 提供非秘密默认值；环境变量只保留 PostgreSQL/Redis 连接配置。
- 保持所有资源关联使用业务 UUID，不向 API 输出自增 `id`；不声明 GORM 外键关系，启动时检查所需表存在且当前 schema 无外键。
- 扩展 Compose 为 PostgreSQL 17、Redis 7 和 API 服务；数据库与 Redis 账号密码通过 `backend/.env` 注入，仓库只保留占位示例。
- 更新 V1 设计文档、Compose 使用说明与环境变量示例；保留用户已移除的数据库账号初始化 SQL 状态。

## 验证方式及结果

- `gofmt`：后端 Go 文件格式整理完成。
- `go mod tidy`：完成，生成并锁定依赖版本。
- `go mod verify`：通过，已下载模块与 `go.sum` 校验和一致。
- `go build ./...`：通过。
- `go vet ./...`：通过。
- `docker compose -f backend/docker-compose.yml config --quiet`：通过。
- `docker compose -f backend/docker-compose.yml build api`：未完成；Docker Hub 拉取基础镜像元数据时网络返回 EOF。
- 使用隔离的 `postgres:16-alpine` 与 `redis:7.4-alpine` 容器完成接口联调；两者分别绑定备用端口 `55432` 和 `56379`，不影响机器上已有服务。迁移成功，运行配置加载了 9 项。
- 对实际数据库 schema 检查到 0 个外键，并确认 `business_id`、手机号、用户归属和灵感图标签 GIN 索引存在。
- 启动本地编译的 API 进程，逐个请求 V1 路由并完成 70 项 smoke checks，全部通过。覆盖注册、登录、刷新和重放拒绝、退出、鉴权、用户资料、标签 CRUD、灵感图 CRUD、分页、any/all 标签检索、跨用户隔离、标签归属和删除清理，以及 PostgreSQL/Redis readiness。
- 另用同一个 Refresh Token 并发发送两次刷新请求，结果为一个 `200`、一个 `401`；随后成功撤销该测试会话。
- 实际数据库集成使用 PostgreSQL 16；由于本机没有 PostgreSQL 17 镜像，且 Docker Hub 拉取返回 EOF，本次未能在 PostgreSQL 17 上重复联调，也未完成 Compose API 镜像构建。

本机共享 Go 模块缓存含有全零模块元数据，校验数据库缓存也损坏。为避免修改其他项目的缓存，本次使用独立临时模块缓存构建；由于本机 SumDB 缓存不可用，`go mod tidy` 期间未完成新依赖的 SumDB 在线校验，依赖校验和已写入 `backend/go.sum` 供后续构建固定使用。

## 未验证内容与限制

- PostgreSQL 17 的容器运行和 Compose 内 API 镜像尚未验证；本轮实际数据库联调采用 PostgreSQL 16。Redis 使用 Compose 同系列的 7.4 镜像。
- 未做并发压力、生产数据规模和故障恢复测试；单次并发刷新竞争已验证只有一个请求能消费旧 Refresh Token。
- Compose 默认让 API 使用 `POSTGRES_USER`；该账号是初始化管理员。生产环境应改用预先创建的受限账号并注入 `DB_USER`、`DB_PASSWORD`。
- 图片上传、OSS 签名、短信验证码、管理端配置接口和生产环境备份/高可用未包含在 V1。
