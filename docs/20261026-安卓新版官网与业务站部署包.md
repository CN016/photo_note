# 安卓新版官网与业务站部署包

## 改动目的与范围

将已构建的安卓 1.0.1 测试 APK 放入独立官网下载产物，并分别生成官网、业务 Web 可直接解压部署的 ZIP，明确服务器更新范围。

本批复用官网现有构建插件和本机公开入口配置，不修改业务代码、下载地址规则或后端版本。官网从安卓 package.json 自动读取 1.0.1，并在构建期间校验、复制真实 ARM64/ARMv7 APK；官网仍标记为调试签名测试版。

## 产物

产物保存在 Git 忽略目录 `frontend/apps/android/artifacts/deployment-20261026-1.0.1/`：

- `website-android-1.0.1-20261026.zip`：官网 `website/dist/` 的完整内容，包含两个 APK、摘要文件及 `releases/android/release.json`。
- `web-20261026.zip`：普通 Web 构建的 `frontend/apps/web/dist/` 完整内容，未使用安卓专用构建目标。
- `部署说明.txt`、`nginx-downloads.conf.example`、`SHA256SUMS.txt`：部署边界、官网静态下载配置示例与 ZIP 摘要。

ZIP 内直接包含网站根目录内容，不增加 dist 包装目录，不含源码、.env、凭据或 node_modules。大体积安装包与部署 ZIP 不提交 Git；本批提交本记录以保存交付边界。

## 验证方式及结果

- `pnpm --dir website build`：类型检查、中英文键检查、公开配置检查和 Vite 构建通过，插件已完成源 APK 与复制后 APK 的摘要检查。
- `pnpm --dir frontend/apps/web build`：普通 Web 类型检查与生产构建通过；存在大包体提示。
- 本地官网预览端口 4178；首页和下载页 HTTP 200 且返回 HTML。
- `pnpm --dir website check:downloads http://127.0.0.1:4178/releases/android/release.json`：ARM64/ARMv7 的完整 HTTP 下载、MIME、长度、SHA-256、摘要文件及缺包 404 检查通过；release.json 版本确认 1.0.1。
- 两份 ZIP 完整性、根目录 index.html、文件数量及解压大小一致性检查通过，生成 SHA-256。
- `git diff --check` 通过。

## 需要部署与尚未验证

1. 业务 Web ZIP 解压到 `https://photo.016imcn.love` 的现有静态站目录，保留原 API 反向代理与 SPA 路由配置。
2. 官网 ZIP 解压到独立官网原 HTTPS 根目录，完整上传 assets/download/licenses/releases 等内容。官网 APK 下载必须使用正确 MIME，缺失文件必须返回 404，禁止回退 HTML；参考现有 `website/deploy/nginx-downloads.conf.example`。
3. 建议先更新业务 Web，再更新官网；保留上一发布目录用于回滚，刷新 HTML 与 release.json 的 CDN 缓存。官网与业务站不得相互覆盖。

不需要部署后端、运行数据库迁移或重启 Redis；安卓用户需要安装 1.0.1 才能获得 APK 内置页面和原生选择器修复。官网只分发手机 ARM64/ARMv7 包，x86_64 包继续保留在本地产物中。

尚未上传生产服务器，没有线上下载、CDN 或安卓真机交互验收结果。本机官网 `VITE_SITE_URL` 为空，未生成正式域名 canonical；本包仍适合原官网根路径部署。详细步骤见交付目录的部署说明。
