# 策划附件上传占位和进度

## 目的及范围

策划正文粘贴或选择支持的文件后，立即在插入位置显示临时媒体块；图片显示本地预览。原图、图片副本和普通文件上传使用浏览器原生 XHR 的实际发送进度；图片准备、处理及创建灵感图分别显示阶段状态，发送完成后显示等待服务器处理。上传成功后替换为正式媒体节点；失败后可重试或移除，多文件按顺序处理。临时块不写入策划文档，用户离开时必须先完成上传或移除失败项。

XHR 上传沿用原有 Bearer 鉴权、401 单次刷新、空间切换及会话代次检查；整个图片处理链绑定原始空间，旧空间的结果不会插入当前策划。新增中英文文案，不新增请求框架依赖或后端接口。

## 验证及限制

- `npm run test`：18 个测试文件、78 项测试通过；上传测试覆盖真实进度事件、Bearer 鉴权、会话切换和 401 刷新重试。
- `npm run typecheck`、Web 生产构建和签名 Android Web 热更新构建结果见交付说明。
- 隔离浏览器和模拟 API 验证粘贴立即出现、40% 进度、失败重试与移除、批量文件顺序、图片两次上传及保存、空间切换后拒绝旧结果。此验证不等于连接真实上传服务。
- 上传百分比表示当前 HTTP 请求已发送的字节，不表示整个图片处理或服务端压缩进度；失败的本地文件只留在当前页面内存中，刷新后不能恢复。未验证真实文件管理器剪贴板、真实网络上传、Android/iOS 真机或线上部署。
