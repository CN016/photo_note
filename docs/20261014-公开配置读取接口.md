# 公开配置读取接口

## 改动目的

为前端提供读取显式开放配置值的接口，同时让所有配置项默认保持私有，避免未登录请求读取未授权配置。

## 主要内容

- 为 `app_configs` 增加 `is_public BOOLEAN NOT NULL DEFAULT FALSE`，以新增的 `000004_add_config_public_flag.sql` 作为增量迁移，未修改历史 SQL。
- 配置模型、统一配置服务和 PostgreSQL repository 支持读取公开配置；repository 始终过滤 `is_public=true`，指定私有 key 时也不会返回。
- 新增无需鉴权的 `GET /api/v1/configs/public`。可读取全部开放项或通过重复 `keys` 参数筛选，响应只包含配置 `key` 和 `value`。
- API 启动时检查 `app_configs.is_public` 已存在；遗漏增量迁移时会直接报出迁移文件位置。
- 更新 `AGENTS.md`、后端设计文档和后端 README，记录默认私有、安全边界与升级方式。

## 验证方式及结果

- 静态核对接口路由位于 Access Token 鉴权分组之外，repository 查询固定包含 `is_public=true` 条件。
- 增量 SQL 使用 `ADD COLUMN IF NOT EXISTS`，并为新字段添加中文字段注释；历史迁移文件未改动。
- `go build ./...` 使用独立 Go 模块缓存通过；`docker compose build api` 和 `docker compose config --quiet` 通过。
- 在本地 PostgreSQL 17.11 容器应用 `000004` 后确认字段为 `NOT NULL DEFAULT false`，并检查开放配置数归零。
- 未携带 token 调用 `GET /api/v1/configs/public?keys=app.mode&keys=http.listen_addr` 返回 `200`，只返回临时开放的 `app.mode`，未返回私有的 `http.listen_addr`；随后已将 `app.mode` 恢复为关闭。
- 未携带 token 调用 `/healthz` 返回 `200`。

## 尚未验证的内容或已知限制

- 配置管理接口不在本次范围内，开放标记需由受控的数据库维护流程设置。
