# 消息中心与 webhook 通知

## 改动目的

为灵感图异步图片处理提供站内完成/失败通知，并允许用户把相同业务事件异步发送到企业微信、钉钉或飞书机器人。创建通知与 outbox 任务后立即结束业务处理链，不让 webhook 响应耗时占用前端请求。

## 主要改动

- 后端新增 `notifications`、`notice_config`、`notice_deliveries` 三张业务表。迁移编号为 `000011`，业务 UUID 有唯一索引，按用户/创建时间、未读状态和投递时间建立查询索引；所有表/字段都有中文注释且不含外键。
- 新增鉴权 API：站内消息分页、未读数、单条/全部已读；用户 webhook 配置 CRUD、测试投递；投递详情和失败任务重试。所有查询以 Access Token 中用户业务 UUID 限定，不向 API 返回数据库自增 ID、完整 webhook 地址或签名密钥。
- `notice.max_webhooks_per_user` 由配置表提供，初始值为 20。新增配置通过锁定用户记录串行校验数量；停用配置仍计数，软删除配置不计数。
- 当前版本的灵感图异步压缩处理成功/失败时，先同时持久化站内消息和每个启用渠道的 outbox 任务。事务检查灵感图 `image_key` 与 `async_version`，事件键按灵感图/版本去重；旧版本或已删除记录不发通知。
- 独立 worker 使用最多 12 秒的 HTTP 超时、不跟随重定向及有限退避重试；平台响应内容不入库，仅保留错误码。站内页面展示每条消息各渠道状态，最终失败任务可单独重试。
- 新增 `/messages` 页面、中英文页面语言包与导航入口。支持未读角标、打开应用期间 30 秒轮询和新消息提示、筛选/已读、关联灵感图跳转，以及三种 webhook 的创建、修改、启停、删除和异步测试。
- 更新根目录 `AGENTS.md`，记录用户端使用方式、通知发布约定、配置上限、投递查询/重试，以及新增通知类型时维护双语文案的方法。更新 `backend/README.md` 和后端版本 `2.3.0`（当前基线已由此前改动升级至 `2.2.0`）。

## 关键接口

- `GET /api/v1/notifications?page=1&page_size=20&unread_only=false`
- `GET /api/v1/notifications/unread-count`
- `PATCH /api/v1/notifications/{business_id}/read`
- `POST /api/v1/notifications/read-all`
- `GET/POST /api/v1/notice-configs`
- `PATCH/DELETE /api/v1/notice-configs/{business_id}`
- `POST /api/v1/notice-configs/{business_id}/test`（立即返回 202，响应包含 delivery business UUID）
- `GET /api/v1/notice-deliveries/{business_id}`
- `POST /api/v1/notice-deliveries/{business_id}/retry`

- [企业微信机器人指南](https://developer.work.weixin.qq.com/document/path/91770)
- [钉钉自定义机器人指南](https://open.dingtalk.com/document/orgapp/custom-robot-access)

实现时分别生成企业微信 Markdown、钉钉 Markdown 和飞书富文本 Post 请求；钉钉和飞书使用各自机器人签名算法。webhook 必须使用 HTTPS、平台白名单域名和标准机器人路径；禁止重定向，日志与 API DTO 不暴露地址凭据及签名。

## 数据库升级

先备份 PostgreSQL，确认早期迁移与工作区中的排期迁移 `000010` 已按既定顺序应用，再手动执行 `backend/migrations/000011_create_notification_center.sql`。本服务不会自动执行迁移；启动检查会验证三张消息表存在。

## 验证

- `go test ./...`（目录 `backend/`）：通过。包含三平台 webhook URL 白名单、对应报文/签名字段、配置响应脱敏及禁止 HTTP 重定向的单元检查。
- `go vet ./...`（目录 `backend/`）：通过。
- `npm run build`（目录 `frontend/apps/web/`）：通过，包含 `vue-tsc --noEmit` 和 Vite 生产构建；Vite 提示已有 wasm bundle 超过 500 KB 阈值，消息页独立脚本约 19 KB。
- 中英文 JSON 键检查：`messages` 71 个递归键、`common` 40 个递归键均一致。
- 本地浏览器访问 `/messages` 后被鉴权路由重定向到登录页，因此未能检查已登录页面的真实桌面/窄屏呈现。
- 未使用实际 PostgreSQL/Redis 进行集成，未执行迁移、真实 webhook 投递或用户数据隔离数据库验证。第三方平台 token 不在仓库中提供。
