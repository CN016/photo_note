# 灵感图压缩改为异步处理

## 目的

缩短灵感图新增和更新接口的响应时间，避免服务端读取、解码及二次压缩图片时阻塞请求。

## 改动范围

- `POST` 新增灵感图和携带有效 storekey 的 `PATCH` 更新先完成同步参数校验与数据库写入，随后将文件压缩、覆盖、SHA-256 和文件大小计算加入进程内后台队列；后台最多并发处理 2 个任务。
- 新增 `inspirations.async_version`，历史记录和新记录默认从 0 开始；带图片的异步更新原子递增版本。同一记录排队中的旧任务会被最新代次替换；后台任务在覆盖图片前复核版本和图片 key，写回元数据时再用相同条件限制，已被新更新替代的任务不会写回记录。
- 更新图片时先清空旧文件哈希和大小；异步成功后填充新值。非图片字段更新及更换为非 storekey 的图片 key 不增加异步版本。
- 新增 `backend/migrations/000007_add_inspiration_async_version.sql` 并在启动 schema 检查中要求该字段；后端版本递增至 `1.1.0`。
- 更新 `backend/README.md` 说明响应和异步失败行为。正常收到退出信号时，服务会在关闭超时内等待已接收的任务。

## 验证

- `gofmt`：已格式化本次修改的 Go 文件。
- `go build ./...`（目录：`backend/`）：通过。
- `git diff --check`（本次修改文件）：通过。

## 未验证内容与限制

- 未连接 PostgreSQL 和真实文件存储验证迁移、并发更新及图片压缩的运行结果。
- 异步处理错误不再作为原新增或更新请求的 HTTP 错误返回；任务失败时 `file_hash` 和 `file_size` 保持为空，重新提交图片 key 可重试。
- 队列只存在于 API 进程内；异常终止可能丢失未完成任务。收到正常退出信号时最多等待既有的 10 秒关闭期限。
