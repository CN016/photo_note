# 安卓启动恢复与进入检查更新优化

## 目的与定位

用户报告清理后台再进入时约20秒仅剩反馈按钮。本次以Web优化为主，原生侧补齐有效凭据复用及每次进入检查APK版本。

使用上一批交付资源与离线合成桥接受控复现：refreshNotificationSession不返回时只剩反馈按钮；同一请求返回后页面正常。根因链路为首个路由等待登录恢复，缺少首屏恢复状态；原生每次启动恢复强制联网刷新，后台刷新时还可能排队后重复刷新。Web失败转登录页时原本还会在路由守卫再恢复一次。没有采集用户手机分段计时，不能把全部20秒断言为某一个网络请求。

## 变更范围

- Web新增StartupRecovery与独立startup中英文命名空间。首个导航未完成即展示状态，超过12秒提供重试；不展示或挂载未授权业务数据。
- 能力探测3秒、原生认证桥接30秒、普通Web刷新15秒、启动用户资料10秒、Web Locks排队8秒分别有限等待。锁超时只限制排队，不中断已开始的轮换；桥接超时不改走旧令牌重复HTTP刷新、不清除凭据。
- 已进入恢复失败状态时转登录恢复页不再自动重复初始化；重试由页面动作触发。
- Web传入被拒绝的Access Token，原生优先复用未过期内存凭据，避免后台刚刷新又重复联网。旧Web/旧壳保持兼容，原生已完成的迟到轮换仍保存到加密保管库。
- 原生每次onStart进入时异步主动检查官网APK清单，绕过一小时检查缓存；共享在途锁合并重复请求，保留小时任务和同版本一小时内不重复弹窗。版本检测不阻塞Web首屏或登录。
- Android升级1.3.1/versionCode 10。无后端、数据库或配置变更，无新增依赖。业务Web、签名资源、三ABI Debug APK和分发APK的独立官网需本批交付。

## 验证

- Vitest定向24项通过：启动桥接超时不清凭据、不走HTTP重刷、失败后的路由恢复不再等待第二轮、旧壳回退、认证和空间隔离等。
- Android9/API28 x86_64模拟器定向9项通过：凭据加密与退出边界、有效缓存恢复不访问fixture.invalid、真实系统通知和退到后台后继续轮询，以及每次进入绕过小时缓存、在途请求合并、同版本提示节流与版本格式校验。使用离线合成数据，不使用真实账号。
- 浏览器对旧交付资源复现仅反馈按钮；新资源实测立即显示恢复状态、12秒后可重试，原生桥接不返回时一轮30秒等待后进入登录恢复页，只有一次刷新调用，凭据保留。放行正常响应后完整消息中心正常显示；中文与英文恢复状态均验证。
- Web最终类型检查/Vite构建/签名资源生成通过；发布号1793892233843。Android三ABI Debug构建及最终Lint通过，0 errors / 17 warnings，保留既有资源/图标与AGP提示。
- 最终官网、APK签名、压缩包完整性与摘要结果记录于本批artifacts交付说明。

## 限制

Web热更新可先改善旧1.3.0的空白等待及失败恢复；有效凭据复用、每次进入检查版本需安装1.3.1 APK。真正冷启动仍须联网恢复，不承诺固定秒数；没有用户设备日志或真实账号端到端计时。未验证实体ARM设备、Android13+权限、Android15+六小时时限或长时省电。沿用Debug签名，未制作正式商店包。无生产部署或Git推送。
