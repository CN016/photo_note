# 安卓登录持久化与页面重载恢复修复（1.1.2）

## 问题与复现

用户反馈安卓更新、清理后台后经常回到登录页，并要求确认是否只是页面重载导致Pinia store丢失。当前Access Token及用户资料本来就只在内存，刷新凭据及空间/会话元数据存入localStorage；每次重新加载必须刷新凭据、请求用户资料并重建store，不能依赖旧store存活。

在Android 9/API28 x86_64模拟器，用不含真实账号的合成localStorage标记复现：写入后立即强制结束进程，重新进入读到null；同一流程在写入后等待10秒再结束进程，能读回标记。说明存在浏览器异步落盘窗口，不是正常内存store重建本身就应退出。此为本地合成复现，不能据此断言所有用户设备的掉登录原因完全相同。

同时发现前端初始化遇到网络/503等临时错误后仍把ready设为true、user置空，后续不再重试初始化，表现成退出。旧实现没有更新时清理全部浏览器数据的调用；本批也不通过清空浏览器缓存修复。

## 修复内容与安全边界

- 安卓1.1.2、安装版本6。新增原生SessionVault：刷新凭据及空间/会话代次用Android Keystore AES-GCM加密并通过AtomicFile原子保存；Access Token、密码、用户资料不落入此文件，凭据不写日志。
- 固定HTTPS代理在登录、注册、刷新及空间切换成功时，先保存可信后端返回的刷新凭据，再把响应交给网页。启动时通过带本机Cookie且禁止缓存的脚本恢复持久凭据，之后仍向后端恢复用户资料并重建Pinia；不保存整个store，避免把跨账号/空间的缓存当作权限依据。
- 显式退出先保存退出标记；仅新登录/注册成功可以覆盖。退出前或已关闭服务的迟到响应、同会话旧空间代次不得覆盖最新凭据；明确撤销当前刷新凭据才清理，网络/503、未知403以及旧凭据的迟到401不清理新状态。
- Web初始化暂时失败保留刷新凭据，维持可重试状态；登录页显示中英文“恢复登录”提示，提供重试、重新聚焦重试及明确退出后重新登录入口。401或组织不可用仍结束会话，不把真实失效凭据当作永久有效。
- Android签名资源更新、APK覆盖安装不主动清除此私有文件；卸载、清除应用数据、密钥失效和服务端过期/撤销不在“免登录”承诺内。修复前已经丢失的凭据无法凭空恢复，需重新登录一次。未更改后端、数据库或Compose。

## 验证及结果

- 新增Pinia恢复回归：重建页面模块及全新Pinia后，仅凭持久刷新凭据恢复用户、组织和会话版本，不调用登录接口；网络失败重试、资料503、明确401、组织不可用和离线显式退出均覆盖。完整前端70项测试通过。
- Web生产构建、类型检查、中英文login键集合检查通过；签名Web更新资源包已生成。
- 原生构建、三ABI APK及Lint通过，Lint为0错误、21警告。AES加密文件不包含明文刷新凭据或Access Token；不同API来源不能解密复用。
- Android 9模拟器最终14项instrumentation通过，覆盖原生加密持久化、退出/代次/迟到请求、真实TLS代理在响应前保存凭据、网络503和未知403保留、旧401隔离、签名资源更新、原生桥接、导出/分享、Canvas及相册。
- 独立的原生进程持久化测试写入后立即强制停止，再由全新仪器进程读取通过，无需等待浏览器落盘。测试使用隔离合成目录，不登录真实账号。
- 本批产物放在 `artifacts/20261027-131047/`，包含Android 1.1.2安装ZIP、业务Web（含签名更新目录）ZIP、官网1.1.2 ZIP、部署说明及SHA-256。压缩包在交付前完成CRC和哈希核对，结果写入本批manifest。

## 发布与未验证范围

先发布本批业务Web资源及android-updates目录，版本包先上传、latest.json最后替换；更新官网1.1.2下载文件，并安装1.1.2 APK。完整的原生可靠持久化需要新APK，单独热更新Web只能获得前端恢复逻辑。APK仍为调试签名，需与已有APK同签名覆盖安装。

后端、PC、iOS和微信小程序未涉及发布，无数据库迁移。未上传生产、未用真实账号验收，未覆盖实体Android/ARM运行或生产签名；桌面浏览器/iOS/小程序的前端恢复逻辑仅通过共享代码测试及构建，未分别实机验证。操作系统在上游刷新已提交但原生尚未收到响应时直接终止进程仍可能需要重登，本批没有放宽后端单次刷新令牌规则。
