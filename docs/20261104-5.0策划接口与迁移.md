# 5.0 策划接口与迁移

## 版本与兼容

产品功能批次为 5.0，后端为向后兼容的 `4.8.0`，遵守项目语义化版本规则。策划正文仍使用版本 1 的 ProseMirror JSON；新信息为独立业务字段，不改写历史正文。旧客户端省略 `shooting`、`manual_summary` 和 `ai_analysis` 时保留现值，显式提交空字符串或空拍摄信息对象可清空对应内容。

普通接口继续使用已校验的会话空间与创建者范围，不接受客户端指定归属，也不继承系统扫描权限。所有资源标识均为业务 UUID。

## 策划字段和状态

`POST /api/v1/projects` 与 `PATCH /api/v1/projects/{business_id}` 新增以下可选字段；更新继续提交当前 `revision`。

| 字段 | 含义 |
| --- | --- |
| `shooting.start_at`、`shooting.end_at` | RFC3339 时间或 null；界面按北京时间录入，结束必须晚于开始且区间最长 24 小时 |
| `shooting.location` | 地点，最多 240 字符 |
| `shooting.person` | 人物称呼，最多 120 字符，不用于账号匹配 |
| `shooting.kind` | 空字符串、`photo` 或 `video` |
| `manual_summary` | 人工总结，最多 100000 字符 |
| `ai_analysis` | 用户编辑或采用的 AI 分析，最多 100000 字符，不参与执行状态计算 |

详情返回以上字段及 `status`、`schedule_id`、`schedule_owned`、`schedule_sync_state`。状态和关联不能通过普通保存请求认领或改写。

- `unfinished`：没有任务项勾选，也没有任务项内非空文字的删除线。
- `executed`：存在上述任一标记，人工总结为 Unicode 空白或空字符串。
- `completed`：存在执行标记，人工总结包含非空白文字。普通正文删除线不计入。

状态在保存事务中从当前正文及人工总结计算。取消标记、清空总结后可回退，不依赖 AI 生成或“完成总结”按钮。

`GET /api/v1/projects` 保留 `q/page/page_size`，增加可选 `status`。响应仍包含 `items/page/page_size/total`，增加 `status_counts`，其 `unfinished/executed/completed` 计数覆盖相同搜索条件下的完整结果。状态筛选和分页在数据库执行，列表不加载正文及复盘文本。非法或重复状态参数拒绝。

## 档期、总结及作品集

| 接口 | 行为 |
| --- | --- |
| `GET /projects/{id}/schedule/candidates` | 返回同空间同用户、时间重叠的工作事项实际发生项，包含重复规则与单次例外；不按地点或人物文字猜测匹配 |
| `POST /projects/{id}/schedule` | 提交 `revision`；可选 `schedule_id` 确认关联，或 `create_new: true` 明确另建，或 `detach: true` 解除关系 |
| `GET /projects/{id}/review` | 查询已创建的独立副本，没有副本时 `data: null` |
| `POST /projects/{id}/review` | 提交 `revision`，复制已保存的非空人工总结；并发和重复提交返回同一副本 |
| `GET /project-reviews?q=&page=&page_size=` | 分页检索独立总结标题与正文，列表仅返回元数据 |
| `GET /project-reviews/{id}` | 读取独立文档 |
| `PATCH /project-reviews/{id}` | 提交 `title/content/revision`，使用文档自身修订号保存；不回写原策划 |
| `GET /projects/{id}/portfolios` | 查询已关联的本人作品集 |
| `PUT /projects/{id}/portfolios` | 提交 `portfolio_ids` 替换当前策划关联；最多 100 个、不允许空 UUID、重复或跨空间资源 |

表中接口均带 `/api/v1` 前缀。保存完整拍摄信息后，接口先保存策划，再处理档期。无候选时自动创建；有候选时返回 `schedule_sync_state: candidates`，由用户确认。同步失败返回 `failed`，HTTP 保存仍成功，策划内容不会因日历冲突丢失。同步指纹避免无关自动保存反复处理档期。

仅本策划创建的单次工作事项允许同步起止时间、标题和内容；用户选择关联的已有档期保持原内容。用户明确解除关系不会删除档期，且相同拍摄信息不会立即自动重建。日历删除会清理同用户同空间的策划关联。以上操作与既有档期写入共用事务锁并重新检查候选及开放时段冲突。

总结标题优先由已有的拍摄时间、地点、人物和类型组成；信息均未填写时回退策划标题。删除策划后保留独立总结及日历事项；当前总结文档没有删除接口。作品集侧原有关联和跳转继续可用。

## AI 配置与请求

管理员通过现有系统配置管理维护以下私有项，固定系统空间 `orgid=-1`：

| 配置键 | 设置 |
| --- | --- |
| `projects.ai.endpoint` | 完整、无凭据及查询参数的 HTTPS `chat/completions` 兼容接口，端口为 443 |
| `projects.ai.model` | 服务端模型名 |
| `projects.ai.api_key` | 密钥，`is_secret=true`、`is_public=false`，不返回明文 |
| `projects.ai.timeout_seconds` | 默认 45，范围 5 至 60 秒；HTTP 写超时应覆盖该时长 |
| `projects.ai.max_concurrent` | 当前 API 进程默认 2，范围 1 至 8；同一策划同时最多一个生成请求 |

`POST /api/v1/projects/{id}/ai-analysis` 提交 `revision` 与 `locale`（`zh-CN/en-US`）。成功返回 `analysis/source_revision` 预览。用户采用后经普通策划保存写入 `ai_analysis`；生成本身不写数据库、不覆盖编辑、不改变人工总结及状态。

只发送标题、拍摄信息、正文文字、动作标记和人工总结；不读取图片、附件字节和资源节点属性中的 storekey、私有资源地址，也不添加账号或空间标识。用户自行写在正文里的文字仍属于本次分析输入。输入文字总量最多 100000 字符，输出也受长度限制。客户端卸载时取消生成请求。

未配置返回 `project_ai_unconfigured`；非法配置返回 `project_ai_invalid_config`；并发占用返回 `project_ai_busy`；超时返回 `project_ai_timeout`；远端失败或非法响应返回 `project_ai_failed`。错误不带密钥、完整服务地址或远端响应正文。客户端禁止重定向、环境代理及内网目标，连接时校验并固定 DNS 解析结果。

## 迁移、验证及回滚边界

已有数据库先持久备份，然后按顺序执行未应用的 `000027_project_summary.sql`、`000028_project_workflow.sql`，再启动 `4.8.0` API，最后部署业务 Web 和 Android 热更新资源。服务启动只检查 schema，不自动迁移。新增表及列包含中文说明，没有外键；独立总结表按空间与作者隔离。

`000028` 回填历史状态并建立完整分类索引，创建独立总结表和默认关闭的 AI 配置。它是一次性版本迁移，不可重复执行。回滚应用后不得假定旧服务继续维护新状态缓存；再次升级前需重新评估回填，不能盲目重复建表迁移。未执行生产迁移或部署。

已在单独的 PostgreSQL 测试容器验证全量迁移、历史状态回填、同组织不同用户和跨组织访问、并发创建副本、并发同步及旧客户端保留字段，并通过保存接口的自动档期测试。外部真实 AI 服务尚未配置，协议与错误处理通过受控测试客户端验证；不能据此声称真实供应商联调已通过。
