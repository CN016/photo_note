# 档期管理与客户预约

## 改动目的

新增独立的档期管理和访客预约流程，帮助工作室安排工作事项、开放可预约时段，并在一个日历中查看客户申请。档期数据与收支账本分开保存。

## 主要内容

- 新增 `/schedule` 管理页和 `/book/:shareToken` 访客预约页。日历提供月历、最近 7 天、最近 14 天和自定义 1–90 天视图；月历展示摘要，日期卡片展示完整内容并随内容增高。
- 档期按 `Asia/Shanghai` 展开，支持单次、每日、每周指定星期、每月同一日重复；月末不存在的日期跳过。重复系列支持编辑整组，也可覆盖或取消单次发生项。重复开放时段要求填写结束日期，系统据此检查整个开放周期的重叠。
- 新增工作事项、开放预约时段、单次例外、预约申请和分享配置四张业务表，以及管理、分享查询和访客申请接口。分享令牌只以 SHA-256 摘要保存；公开接口仅返回开放时段和剩余名额。
- 预约申请在数据库事务中核验仍有效的分享令牌、锁定开放时段、释放过期申请并检查容量后写入。申请待确认保留 24 小时；确认继续占位，拒绝、过期或拥有者取消后释放。公开申请使用 Redis 按可信客户端 IP 限流，限额位于私有配置中。
- 后端版本升至 `2.2.0`，新增 `000010_schedule_management.sql`，并在接口设计文档中记录路由、字段、权限和容量规则。

## 验证方式及结果

- `go test ./...`：通过。
- `go build ./...`：通过。
- 使用 `PHOTO_NINI_SCHEDULE_TEST_DSN` 运行 `go test ./internal/store -run TestScheduleStoreIsolationCapacityExpirationPrivacyAndRevocation -count=1`：通过。用例覆盖用户隔离、公开字段隐私、同一时段并发申请只成功一位、待确认申请过期释放名额及分享链接撤销。
- `pnpm test`：通过，5 个测试文件、16 项测试。
- `pnpm build`：通过；构建输出提示现有 WASM bundle 超过 500 KB。
- PostgreSQL 迁移验证：在单独测试数据库顺序应用 `000001` 至 `000010`，再执行上述集成用例，全部通过；验证后删除测试库。另在现有本地库用 `ROLLBACK` 演练检查 DDL、索引、配置插入和中文字段注释，没有留下迁移数据。演练发现旧固定配置 UUID 与既有记录冲突，迁移已改为 `gen_random_uuid()` 并复验通过。
- 使用模拟 API 数据检查 Web 页：375、768、1024、1440px 下无页面横向溢出；375px 的 7 天卡片宽 327px，768px 的 14 天卡片宽约 225px，1024px 约 219px，1440px 约 147px。长内容卡片按内容增高；375px 自定义 21 天视图为单列且无横向溢出。已检查中英文切换和公开预约表单提交后的申请编号展示。

## 尚未验证及限制

- 浏览器使用模拟 API 响应；数据库集成用例验证了账户查询隔离、并发容量、过期释放、分享撤销及公开返回字段，但未在已部署的真实认证环境端到端验证预约审批和 Redis 限流，也未执行生产规模并发压力测试。
- 未将迁移应用到现有开发库或生产库；版本化迁移已在独立临时数据库执行并随后删除。生产代理链的客户端 IP 解析仍需部署环境验证。
- 明暗主题、原生 PC、iOS、Android 和微信小程序壳尚未逐一真机验证。
- 首版没有短信或邮件通知；预约拥有者需在管理页处理申请并线下联系访客。
