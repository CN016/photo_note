# 文件上传与健康检查调整

## 目的

为后端增加按 `storekey` 读取的本地文件上传能力，公开健康检查，并支持通过配置表选择新文件的存储类型和单文件大小上限。

## 改动范围

- 新增 `POST /api/v1/files` 与 `GET /api/v1/files/{storekey}`。两条文件路由需要有效 Access Token；文件不保存元数据、不绑定 `user_id`，不提供列表、删除或自动清理接口。任何已鉴权且持有有效 key 的用户均可读取对应文件。
- `storekey` 使用 `<type>_yyyymmdd_uuid.ext` 格式。本地文件按 `<root>/yyyymmdd/<uuid前三位>/<uuid>.<ext>` 保存；读取时根据 key 前缀分派。V1 仅实现 `local`，`oss` key 和配置可识别，但 OSS 后端未接入时返回 501。
- 新增配置项 `files.active_store_type`、`files.local_root`、`files.max_upload_bytes`。上传时重新查询当前存储类型；本地根目录和上传上限在服务启动时加载。默认根目录为 `/var/lib/photo-nini/uploads`，默认单文件上限为 50 MiB。
- Docker Compose 将上传目录挂载到 `uploaded_files_data` 命名卷；Dockerfile 为非 root 服务账号创建并授权默认目录。Git 和 Docker 构建上下文忽略本地 PostgreSQL 数据、上传文件和镜像导出目录。
- `/healthz` 改为无需 token 的 readiness 路由。上传大小超限返回 413。

- `go test ./...`：通过；当前后端包没有 Go 测试文件。
- `docker compose config --quiet`：通过。
- 本地 Docker Compose 使用 PostgreSQL 17.11、Redis 和 API 启动成功；应用并验证 `000003_seed_file_storage_config.sql` 中的文件配置。
- HTTP smoke 通过 32 项检查，覆盖注册、登录、刷新重放拒绝、退出、用户资料、标签和灵感图 CRUD、公开健康检查、文件接口 token 校验、本地上传下载字节一致性、storekey 格式、跨用户按 key 下载、非法 key、OSS key 路由、50 MiB 配置上限和上传时动态切换存储类型；空标签更新问题另见[修复记录](20261014-修复灵感图标签清空.md)。
- PostgreSQL 实际 schema 外键数量为 0；smoke 数据及上传样本已清理。
- Docker 镜像构建通过。一次增量构建遇到镜像代理 502，随后使用已下载的基础镜像摘要完成构建；Compose 默认镜像源未修改。

## 限制

- OSS 客户端和凭证配置尚未实现，`files.active_store_type=oss` 时新上传返回 501；读取 `oss_...` key 也返回 501。
- 文件大小上限和本地根目录在服务启动时读取；修改这两项配置后需重启 API。存储类型在每次上传时读取，修改后对下一次上传立即生效。
- 本地文件没有用户归属或自动保留策略，生产部署需自行保障命名卷容量和备份。
