# 线性短动画与首帧裁切对齐

## 目的

按最新反馈将详情开合设为约180ms线性动画，同时消除列表图片到动画首帧的裁切和比例跳变。

## 改动

- 窗口位移缩放、图片边界过渡及像素交接统一使用线性曲线。位置动画160ms，交接20ms，正常时序约180ms；不增加回弹或缓入缓出。
- 捕获来源图片框尺寸，以列表居中cover裁切计算完整图片的初始边界，并补偿根节点横纵不同的缩放。保留清晰详情像素，首帧看到的区域与列表一致，再展开到完整详情图。
- 图片快照的CSS宽高固定，运动仅更新x/y/scale变换，不再逐帧修改位置和宽高布局属性，减少布局及重绘开销。
- 统一时长与曲线常量，窗口和图片使用相同参数。不设置固定低帧率或伪造中间帧，实际更新仍跟随设备requestAnimationFrame。
- 保留列表详情预加载、原位展开返回、底部导航、抽屉、锚点和备注。

## 验证

- `pnpm.cmd --dir frontend/apps/web test`：31个文件、132项通过。新增横图/竖图/方图首帧cover映射及比例补偿验证，更新线性时长和仅变换动画断言。
- agent-browser/Chromium 390×844加载真实动效模块，合成画布验证：0/40/80/120ms窗口宽度约160/217.5/275/332.5px，线性递增。
- 打开前与零进度首帧截图在160×190来源区域比较，RGB平均绝对差约0.076/0.037/0.009色阶，边缘存在重采样差异，未出现裁切位置及比例突变。
- 合成场景4次线性热运行，包含0/40/100ms详情就绪与返回，窗口耗时采样约152–158ms（测量从初始化后开始），最大采样帧间隔约6.5–6.9ms，展开宽度单调，结束后快照释放。
- `git diff --check`通过。正式类型检查、构建、Android签名和交付校验结果见本批交付README。

## 限制与发布

未进行真实列表端到端、真实后端或Android/iOS/PC真机测试；合成场景采样不能保证设备实际帧率。180ms缩短了可显示的总帧数，不意味着超过屏幕刷新率。异常迟到的画布仍需先对齐再交接，不承诺慢加载总耗时180ms。

需发布业务Web及Android签名Web热更新；不涉及官网、后端、数据库、原生壳和小程序代码。未上传、部署或线上验收。
