# 安卓每小时 APK 版本更新提醒

## 目的与发布范围

Android **1.2.0 / versionCode 8** 增加 APK 新版本检测和升级确认。用户确认官网为 `https://www.016imcn.love`，已设置官网实际 `.env` 与示例的 `VITE_SITE_URL`。交付 Android 三 ABI 调试包、www 官网包以及本次构建对应的业务 Web/签名资源包；未改变后端、数据库或 Compose。

## 实现与交互

- 前台首次打开检查，持续运行时按一小时门槛检查；恢复前台时补查到期任务。网络请求在独立线程执行，不阻塞编辑器启动。
- 原生 `JobScheduler` 注册持久化的一小时周期、五分钟弹性窗口任务，要求有网络；没有新增调度库。后台只保存版本结果，不在其他应用前台强行弹窗，回到取景台且引擎已就绪后再提示。
- 前台和后台通过同一个独立 SharedPreferences 状态领取检查；后台门槛兼容系统五分钟窗口，避免提前几分钟执行就跳过整个周期。正常前台仍按一小时门槛，重复启动/并发触发不重复请求。
- 新版弹窗展示版本、“稍后再说”和“前往官网下载”。同版本一小时内最多提示一次，安装更高版本或官网回退到当前版本后不再提示。跳转只发出 `ACTION_VIEW + CATEGORY_BROWSABLE`，使用系统外部浏览器，固定打开 `/download/`，不在 Gecko 可信页面中加载官网，不自动下载/安装 APK。
- 版本检查源固定为官网 `/releases/android/release.json`；由构建变量生成 `apk-update-config.json`，不提交生成配置。支持 `PHOTO_NINI_APK_RELEASE_URL` 和 `PHOTO_NINI_DOWNLOAD_PAGE_URL` 同源路径覆盖，拒绝 HTTP、凭据、查询、片段和跨源跳转。
- 版本记录通过 HTTPS 读取，禁止重定向，连接 4 秒/读取 6 秒超时，正文最大 64KiB并有读取期限；不携带账户凭据。异常/离线/旧清单静默保留上次确认结果，不退出登录、不清除用户缓存。
- 官网插件在校验真实 APK 与摘要后，自动生成 `schema:1`、`versionCode`、`version`、`channel`，保留既有下载字段。比较 Android 安装版本号而不是字典序比较版本文本，并区分 debug/release 渠道。当前官网分发的是调试签名测试包。
- APK 提醒与原有签名 Web 资源热更新相互独立：只发布 Web 不会触发 APK 升级弹窗；原有启动检查、回退和编辑中不强制刷新的行为不变。
- 新增权限只有普通的网络状态与开机恢复权限；JobService 受系统 `BIND_JOB_SERVICE` 保护。不申请通知、悬浮窗、精确闹钟、安装包安装权限。
- 更新原生中英文资源、Android/官网维护说明及官网 scoped AGENTS 版本记录约束。无新增业务 Web 文案或后端接口。

## 实际验证

- Node 构建脚本测试 **3 项通过**：官网配置、安全地址、空配置/注释行、签名资源处理。
- Android Web 类型检查/Vite 构建、三 ABI `assembleDebug`、`lintDebug` 通过；`assembleDebugAndroidTest` 通过。
- Android 9 API28 x86_64 模拟器完整原生 **22 项通过**；包含真实原生更新弹窗、“稍后”去重、外部浏览器 Intent 拦截、周期/持久化/网络约束检查、真实 TLS 版本检测与小时/弹性窗口节流、异常大清单、旧版本/渠道/非法版本、相册/缩放/会话/热更新原有回归。
- 强停后另一次新进程会话恢复 **1 项通过**。系统任务可强制触发并回到等待状态；强停移除任务后，重新打开应用恢复登记。没有实际等待一小时或做整夜休眠/系统重启测试，小时门槛使用受控时间推进和 JobInfo 定义验证。
- 原生中英文资源键一致；官网 `pnpm build`（类型、语言、配置检查）通过。
- 官网本地预览：下载页 canonical 为 `https://www.016imcn.love/download/`，中英文切换正常，显示 1.2.0；版本清单为 `schema=1/versionCode=8/channel=debug`。两份 ARM APK 的 HTTP、MIME、长度、SHA-256、摘要文件与缺失文件 404 全部通过。
- APK 实际 manifest 为 `versionCode=8/versionName=1.2.0`；签名 Web 的 RSA-SHA256 验证通过。交付压缩包另检查完整性、逐文件摘要与 APK 内置 Web 发布号一致性。

## 限制与发布

- 不能保证后台精确到每小时整点：Android 周期任务受省电、无网络与系统/厂商策略限制，见 [Android JobInfo 文档](https://developer.android.com/reference/android/app/job/JobInfo.Builder)。强制停止后需重新打开应用恢复任务；无可用浏览器时显示本地提示。
- 未验证实体 ARM 手机、Android 16、长时后台/重启及真实外部浏览器下载/安装流程。测试拦截了升级 Intent，未真的通过外部浏览器打开官网或安装未来 APK。iOS、PC 和微信小程序不受本原生功能影响，未构建/运行。
- 安装包为 Android Debug 调试签名，不是正式商店发行包；正式渠道需要对应 release 清单和签名。仅提供当前调试渠道的官网分发，不承诺跨签名覆盖安装。
- 先部署 www 官网包（包含真实 APK 与 `releases/android/release.json`，清单建议 `Cache-Control: no-cache`），再覆盖安装对应 ABI 的 1.2.0 APK；需要同步本次页面资源时部署 photo Web 包及完整 `android-updates/`。首次获得本原生功能必须安装新版 APK。
- 后续发 APK 同时递增壳版本和安装版本号，先构建 APK，再构建/部署官网；不要只抬高清单版本。后端维持 4.2.1，无数据库迁移、无 API 镜像变化。
- 仅本地交付，未上传或部署生产；最终包、提交、发布号和 SHA-256 见本批根 `artifacts/<北京时间>/README.md` 与 `SHA256SUMS.txt`。现有 AGP compileSdk 37.2、大分块和 Windows Node shell 提示仍存在。
