# 服务端错误日志与管理员通知

## 改动目的

为灵感图首次保存等服务端故障保留可定位的原因、源码文件和行号，并将数据库写入及管理员通知移出 HTTP 请求处理路径。

## 主要改动

- 新增 `error_logs` 表和版本迁移 `000012_create_error_logs.sql`。同一源码文件和代码行在一分钟内重复出现时聚合到原记录并增加 `occurrence_count`；缺少源码位置时按错误码和原因类型区分，间隔超过一分钟则创建新记录。
- 统一 HTTP 5xx 和灵感图图片处理、站内通知 worker 的可恢复后台错误会非阻塞地进入容量 512 的进程内队列。后台 worker 负责输出详细标准日志、写表和管理员通知；PostgreSQL 错误只保留结构化 SQLSTATE 等信息，避免记录用户输入或数据库返回值。
- 启动失败会在标准输出中记录脱敏后的错误摘要；此时数据库日志 worker 可能尚未启动，因此不能保证写入错误日志表。
- 增加私有系统配置 `error_logs.notify_admin` 和 `error_logs.admin_phone`。启用通知时按手机号查询现有用户，并只在站内消息中提示错误码与源码位置；不创建 webhook 投递。
- 消息中心增加错误日志通知的中英文展示。后端版本从 `2.3.1` 升至 `2.3.2`。

## 验证方式及结果

- `gofmt`：已对本批 Go 文件格式化。
- `go build ./cmd/api`：通过。
- `npm run typecheck`：通过。
- 中英文 `messages` JSON：解析成功，键集合一致。
- 备份本地 PostgreSQL 后应用新迁移 `000012`；启动检查随后发现本地库尚缺已有迁移 `000009`、`000010`、`000011`，这三份独立建表迁移已补齐。错误日志表有 19 列中文注释，错误日志和消息表外键数为 0，两项新配置均为私有。
- Compose API 镜像构建成功，`GET /healthz` 返回 `status=ok`、`version=2.3.2`，容器处于运行状态。错误表当前为空；没有人为制造故障请求。

## 尚未验证内容与限制

- 老的请求记录只包含 `cause_type`，无法从历史日志还原这次首次保存失败的真实底层原因；部署后新发生的 5xx 会带上安全摘要和源码位置。
- 手机号配置默认为空；设置为已注册管理员手机号后才会收到站内通知。通知配置按错误日志新增事件实时读取。
- 应用前本地 PostgreSQL 数据备份位于系统临时目录 `photo-nini-pre-000012-20261016.dump`；备份本身未执行恢复演练。
- 队列是有界内存队列。满载时请求仍不等待，后台会输出丢弃数量；进程异常退出时尚未持久化的排队项也可能丢失。数据库启动失败等发生在错误日志 worker 创建之前的故障仍只会进入进程标准输出。
