# Nginx 后端反向代理

## 改动目的

为 Web 站点提供统一 `/backendApi` 入口，将前端 API 与后端 readiness 请求同源转发，避免生产环境依赖后端 CORS 配置。

## 主要内容

- 新增 `frontend/apps/web/deploy/nginx-backend-api.conf`，适用于包含在站点 `server {}` 内的 Nginx 配置片段。
- Nginx 将 `/backendApi/` 后的路径原样转发到后端，移除 `/backendApi` 前缀；例如 `/backendApi/api/v1/...` 映射为后端 `/api/v1/...`，`/backendApi/healthz` 映射为 `/healthz`。
- 代理上游默认是后端 Compose 发布到宿主机的 `127.0.0.1:8089`。若 Nginx 与 API 不在同一宿主机网络，应调整上游地址。
- 上传请求上限设为 `60m`，为后端默认 50 MiB 文件上限留出 multipart 请求开销；如后端 `files.max_upload_bytes` 提高，应同步调整 Nginx 限额。
- 前端 API 与健康检查统一请求 `/backendApi`；Vite 开发代理也会剥离该前缀，因此开发和生产路径一致。

## 验证方式及结果

- `pnpm typecheck`（工作目录 `frontend/apps/web`）：通过。
- 当前 Windows 环境未安装 Nginx，无法运行 `nginx -t`；配置按 Nginx `location` 与带 URI 的 `proxy_pass` 前缀剥离规则进行静态核对。
