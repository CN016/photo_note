# 反馈中心管理员回复

## 改动目的

允许管理员在反馈中心直接回复文字并附带图片；登录用户通过站内消息和已启用 webhook 收到回复，游客反馈只保存回复数据。后端版本递增至 `2.10.0`。

## 主要内容

- 迁移 `000019_feedback_replies.sql` 为 `feedbacks` 增加 `reply_content` 与 `reply_image_keys`，字段有中文注释且不增加外键。
- 管理反馈列表返回回复字段；管理员专用 `PATCH /api/v1/atelier-7f3c9a2e/feedbacks/{business_id}/reply` 接收 `reply_content`、JSON 数组 `kept_image_keys` 和重复 `images` 文件字段。
- 回复文字沿用 `feedback.max_text_chars`；回复图片最多五张并受 `files.max_upload_bytes` 限制，服务端校验实际图片内容并存入公共 key。只能保留当前反馈已有的回复图片。
- 回复、站内 `feedback.replied` 消息和已启用 webhook outbox 在同一数据库事务内提交。注册用户每次保存非空回复都会生成新通知；清空回复或游客反馈不会通知。事务失败时回滚回复并清理本次新上传文件。
- 工作台支持编辑、预览、移除和保存回复图片；消息中心展示回复文字与图片。飞书有凭证时沿用原生图片上传，没有凭证时发送可点击的公共图片链接。
- 回复图片通知使用私有配置 `http.public_base_url` 生成 HTTPS 链接，不使用请求 Host。移除旧图片不删除文件，以免影响已发送的通知链接。
- 更新 `console`、`messages` 中英文文案以及 `docs/backend-design-v1.md` 的字段、行为和接口说明。

## 限制与未验证内容

- 未在本次运行中向真实 PostgreSQL 应用迁移，也未执行带真实用户和 webhook 渠道的端到端请求；部署前需按顺序应用 `000019_feedback_replies.sql`，并确认 `http.public_base_url` 对外可通过 HTTPS 访问。
- `public_` 图片链接可被持有链接的人访问。旧回复图片文件不会自动删除，V1 文件存储没有通用文件管理接口。
- 飞书原生图片投递依赖已配置的飞书应用凭证和图片资源上传权限；缺少凭证时使用可点击链接。
