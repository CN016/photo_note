# 后端版本号与健康检查

## 改动目的

为后端建立明确的版本递增规则，并让部署或运维人员能通过公开健康检查识别当前运行版本。

## 主要内容

- 在 `AGENTS.md` 规定后端使用语义化版本；每个后端改动批次必须递增版本，并说明 PATCH、MINOR、MAJOR 的适用范围。
- 新增 `backend/internal/version/version.go` 作为唯一版本来源，首个版本为 `1.0.0`。
- `/healthz` 成功响应增加 `data.version`，直接读取统一版本常量，仍保持无需鉴权。
- 更新 V1 接口设计和后端部署说明。

## 验证方式及结果

- `gofmt`、`go build ./...`、`go test ./...` 和 `go vet ./...` 成功；当前 Go 包没有测试文件。
- `docker compose build api` 成功；本地 API 容器已重建并保持运行。
- 无鉴权请求 `GET /healthz` 返回 `data.status=ok` 和 `data.version=1.0.0`，与 `version.Current` 一致。
- `git diff --check` 通过。

## 尚未验证的内容或已知限制

- 本版本号在源码中维护；每批后端改动需要按 `AGENTS.md` 手动递增，并在构建发布镜像前完成。
