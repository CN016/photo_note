# 交付模块设计与实施

## 目标与确认范围

交付是使用现有账号、空间、存储服务的独立子应用。同标签页进入 `/delivery`，任务 `/delivery/tasks/:id`，客户 `/d/:token`。不渲染原应用 Banner、侧栏、底部导航、悬浮消息及反馈入口，不设返回原应用按钮；通过浏览器历史返回。模块内阶段切换不新增历史。

四个管理页为上传底片、筛选底片、用户选片、交付精修。查看页面不改变业务阶段；状态变更由明确操作提交。摄影师可以跳过筛选，发布全部未排除照片。客户不需要摄影师账号。

## 压缩设计

原始上传文件按字节保留，预览是私有衍生文件。选片使用预览，原片导出使用原始文件。预览移除 EXIF/GPS，按 EXIF 校正 JPEG 方向，不放大小图。优先限制长边 2560 像素，在 JPEG 质量 92 至 76 中搜索满足体积的最高质量；仍超标时从已校正原图继续缩小尺寸，再重新搜索，不持续压缩上一轮 JPEG。目标是兼顾查看效果和带宽，不能保证所有图片在 1MB 下保持原图级细节。拒绝超安全像素上限和不支持的图片，不以空白图替代。精修原文件也保留，客户下载原始精修文件。

## 数据与安全边界

任务、照片资产、选片轮次、状态记录独立建模。轮次保存已发布照片 UUID 快照和当轮规则；历史正式提交不可被新一轮覆盖。所有管理操作由 `tenant.Scope` 限制 orgid/user_id，数据库业务 UUID 为接口标识，无数据库外键。客户令牌仅保存 SHA-256 摘要，通过受控解析收窄到任务创建者空间；不得凭客户端 storekey 认领文件。访问码只存慢哈希；文件内容通过任务和发布清单二次授权。分享不沿用作品集永久公开图片机制。

## 验证与交付

本文件随实现持续补充实际接口、状态转换、验证结果及限制；未完成清单不作为已实现能力。数据库迁移只对独立测试库运行，不操作现有业务库。最终按真实影响交付业务 Web、Android 签名资源、API 镜像；原生桥接未变时不制造新 APK。构建、打包和线上部署分别记录。


## 实际页面与交互

### 摄影师入口

PC 原应用侧栏新增交付，移动工作台新增交付。独立工作区保留主题和语言切换、交付名称和当前任务设置。任务列表支持名称/客户搜索、状态过滤；当前列表最多返回最近 500 个任务。进入任务保留浏览器历史，四阶段按钮仅修改本页 tab，不新增浏览器历史。不提供返回主应用按钮。浏览器刷新或关闭存在未保存选择/上传队列时使用标准离开确认。

### 新建与设置

名称必填（120 字符）；客户称呼（120 字符）；客户可见说明和内部备注分开。不限/最多/必须选满三种数量规则，限制 1—10000 张。选片截止、分享截止使用带时区时间；下载底片原文件默认关闭，下载精修默认允许。访问码留空保留旧值，显式清除才删除；不能读回已保存口令。规则和选片截止在发布轮次时冻结，修改任务设置后需要重新发布选片才应用到新一轮；分享截止和下载权限即时生效。

任务状态为 active / paused / completed / archived / cancelled。暂停、归档、取消停止客户访问；恢复 active 可重新开放仍有效的链接。只有发布精修后才允许标记完成。完成状态保留查看和下载，停止修改选片。归档不是删除，不自动删除底片或精修。

### 底片上传和筛片

支持多选、PC 文件夹选择、拖入文件（不保证拖入整个目录的浏览器兼容性）。目录选择按相对目录分组；手工指定分组优先。JPG、PNG、WebP、静态 GIF 可生成预览。动画、损坏图片及超限像素拒绝；RAW、HEIC、TIFF 等此入口不直接处理，RAW 应上传同名选片 JPG，再用本地原片匹配导出。单张照片的上传与预览生成为一个请求，前台串行队列显示等待/上传并生成预览/完成/失败。可停止后续队列、重试失败；已成功资产不会因刷新丢失，刷新不恢复尚未上传的 File 对象，也没有分片断点续传。

服务端解码并发固定为一个安全槽，最多解码 4000 万像素；先读受限字节再校验解码尺寸。原件 SHA-256 用于同类型、同分组重复检测。落库前再次验证任务版本、空间、状态、照片数和总容量；失败回收本次新文件。原件、完整压缩预览、网格缩略图三层分离，网格延迟加载并分页（60 张）；卸载释放 Blob URL。未经发布的补传不会自动进入客户现有轮次。

摄影师可以批量保留、排除、重置标记、调整分组；大图查看支持按钮切换和获得焦点后的键盘左右切换。排除不删除原文件。精修页可以人工关联同任务底片，跨任务源 UUID 被服务层拒绝。

### 发布与客户选片

publish：发布当前所有未排除底片；可以跳过筛选。没有可选照片、精确选满数量超过照片总数、截止已过时拒绝发布。存在开放轮次时需要使用重新发布操作，而不是重复 publish。

reopen：创建递增新轮次；冻结新照片清单和新规则，旧轮次标记 superseded，保留旧照片清单、提交时间和已选内容。仍存在于新清单的旧选择带入新草稿，但客户必须重新提交。退回不会自动复用历史备注到新草稿。当前任务选择界面不会把补传或摄影师后续筛选标记动态混入既有清单。

客户默认共同使用同一份选择，不创建独立席位。点击选择或填写备注后延迟 700ms 自动保存，单页仅一个请求在途；新增操作在返回后继续同步。服务端校验轮次和草稿版本，多个设备并发冲突返回 409。失败保留本页选择，可重试或显式采用服务器结果。未保存草稿仅保留于当前标签页 sessionStorage，key 为令牌摘要，不保存访问码或令牌；恢复时检查轮次和照片范围，服务端版本有变化则要求人工选择保留草稿或采用服务端。浏览器禁用会话存储时保留内存草稿和离开确认。

正式提交校验数量、照片范围、重复 UUID、备注范围和长度。必须选满只在提交时要求精确数量，草稿可少选；最多模式允许少于上限，包括零张。提交后锁定；重复同清单正式提交幂等返回。摄影师确认后进入 retouch。客户备注包含整单和逐张，摄影师可以查看。

### 分享

随机 32 字节令牌使用 base64url，数据库仅存 SHA-256 摘要；每次生成新链接都会撤销上一条，二维码与链接成套更新。UI 会先确认重置影响。链接使用已有 VITE_PUBLIC_WEB_BASE_URL 或 Android 更新地址推导的外部 HTTPS 站点，不使用 Android 本地服务地址。没有可用公网 HTTPS 基址时不能生成可用二维码，不虚构域名。

客户链接无需账号；访问码在请求头 X-Delivery-Code 中携带，只存页面内存。分享校验先定位任务，再建立创建者原始 tenant.Scope。每次文件访问继续校验资产属于任务、当前照片快照或精修发布批次、下载开关。私有文件始终经 FileService 归属校验，不创建作品集式永久公开副本。响应 no-store；链接重置、过期、暂停后的新请求被拒绝。已经下载的文件无法远程撤回。

公开接口有单进程每 IP 每分钟限流，采用 Gin 受信代理配置解析 IP，访问码 Argon2id 与解码共用有界槽。多实例部署目前不是共享 Redis 限流，需要网关配合；大量共用出口的客户可能共享限额。

### 原片匹配与导出

摄影师可下载 TXT 文件名清单、包含资产 UUID/文件名/分组的 CSV；CSV 正确转义引号和逗号，并规避公式执行。选择本地原片目录时，优先完整文件名和可匹配目录，再尝试不含扩展名的主名，以支持 JPG 对 ARW/CR3。重复文件名有多个候选时不自动选择，必须人工指定；未找到单独显示。只有全部照片匹配明确后才允许导出本地原片 ZIP。原件不会被移动、覆盖或删除。

本地导出使用存储型 ZIP，包含 CRC32 和中央目录；以资产 UUID 子目录防止同名覆盖。浏览器本地导出限制 256MiB，Android 受已有 32MiB 原生桥接限制，预留开销后约 31MiB；超限提示导出清单在本地工具处理。未新增目录写入、复制或专用修图软件插件桥接。

服务器导出使用独立 delivery_exports 作业：冻结原始版本和照片 UUID 清单，202 只表示接受。相同版本、用途、公开权限及清单复用等待/运行/已完成作业；失败后可重新创建。管理端底片导出仅使用正式提交或已确认选片。客户不得访问摄影师管理端作业。分包子集也必须通过服务端完整授权范围校验。

worker 单进程串行流式写临时文件，逐文件更新进度；ZIP 不在后端内存累积所有原片。5 分钟租约可恢复，最多 3 次领取，旧尝试禁止回写。成功包通过 FileService 登记为私有文件。业务版本改变后旧作业不能完成或下载。页面按平台能力自动分包：Android 约 31MiB，Web 256MiB；单文件超过平台上限时不承诺导出成功。关闭页面不取消数据库作业，稍后相同请求可复用。HTTP 下载暂未实现断点续传。

临时 ZIP 默认保留 24 小时，worker 只删除已结束作业中登记的临时包，不扫描或删除照片目录；失败作业也可到期清理。底片与精修不因 ZIP 到期被删除。机器被强制终止时遗留的系统临时文件尚无跨进程清理机制。

### 精修交付

精修独立资产，不覆盖底片。按唯一完整主名自动关联底片，有歧义时留待人工关联，允许赠片/未关联成品。可上传同一来源的不同文件，形成多份成品；当前没有覆盖旧版本文件的专门入口，以补传新资产/新批次交付。

先草稿，点击发布后全部未发布精修形成下一批次；可以分批交付。界面显示选片数、精修数、已关联数和仍未关联精修的底片文件名，允许明确分批发布，不强制赠片也必须关联。客户可查看已发布精修、按权限下载原文件/分包、显式确认收片。打开页面、发起下载和确认收片不混为一谈。发布新批次重置收片确认。

### 通知与记录

selection_submitted / reopen / publish_final / received / export_completed / export_failed 通过持久化业务事件转为站内消息和各启用 webhook outbox。通知创建、outbox 和事件已处理标记同事务提交，稳定事件键避免重复。事件代次已变化时跳过过期通知，不能保证每个中间过程均外发。外部发送由现有 NoticeService worker 执行，业务 HTTP 不等待 webhook。消息载荷仅含安全事件分类和任务 UUID，不携带照片、客户备注或分享链接。消息页更新中英文标题、正文和交付跳转。

## 表、接口和代码定位

新增表：delivery_tasks、delivery_photos、delivery_rounds、delivery_events、delivery_exports。全部包含 integer 内部主键、UUID 唯一业务标识、orgid、user_id 和带时区时间；无外键。索引以 orgid 开头覆盖用户/任务查询，轮次唯一约束包含 orgid/user_id/task_id/number，分享摘要保持全局唯一。所有表和字段均有中文 COMMENT。

管理 API（/api/v1 前缀）：

| 方法 | 路径 | 行为 |
|---|---|---|
| GET / POST | /deliveries | 最近任务 / 创建 |
| GET | /deliveries/:business_id | 管理详情与历史 |
| POST | /deliveries/:business_id/actions | version + action + 参数 |
| POST | /deliveries/:business_id/photos | multipart: file/kind/version/group_name |
| GET | /deliveries/:business_id/photos/:photo_id/file | original=1 原文件，thumbnail=1 缩略图，否则完整预览 |
| POST | /deliveries/:business_id/exports | kind + 可选 photo_ids；202 返回业务 UUID |
| GET | /deliveries/:business_id/exports/:job_id | 状态和实际进度 |
| GET | /deliveries/:business_id/exports/:job_id/file | 完成且代次有效才下载 |

客户 API 以 /api/v1/delivery-shares/:token 为前缀，使用可选 X-Delivery-Code：

| 方法 | 后缀 | 行为 |
|---|---|---|
| GET | 空 | 当前公开详情 |
| PUT | /selection | round/version/selected_ids/notes/submit |
| POST | /receive | 显式确认收片 |
| GET | /photos/:photo_id/file | 按发布清单与下载权限读取 |
| POST | /exports | 创建客户可访问的分包作业 |
| GET | /exports/:job_id | 客户作业状态 |
| GET | /exports/:job_id/file | 下载客户可访问的完成包 |

actions：settings、share、revoke、status、stage、mark、group、link、publish、reopen、confirm、publish_final。操作携带当前任务 version，冲突 409；跨空间、跨用户、跨任务 UUID 统一隐藏存在性。stage 只直接支持 upload/cull，以及已确认选片后的 retouch；select/delivered 由发布动作推进。

前端：DeliveryPage.vue / PublicDeliveryPage.vue 路由包装，DeliveryWorkspace.vue 共用工作区但使用独立页面 i18n 命名空间；DeliveryImage.vue 私有预览生命周期，delivery/matching.ts 和 localZip.ts 处理本地导出。

后端：model/delivery.go；service/delivery*.go；store/delivery*.go；httpapi/delivery.go；imagecompress/delivery.go。main 装配两个后台循环，文件服务与通知服务复用既有实现；tenant_scope.go 登记全部新表，postgres.go 启动时检查表存在。

## 配置、迁移和版本

后端版本：4.8.1 → 4.9.0（兼容新增功能）。迁移：backend/migrations/000029_delivery.sql。已有环境先备份，再按顺序执行所有未应用迁移，然后启动新版本；不执行 AutoMigrate。此次仅新增表和私有系统配置，不猜测旧数据归属，不迁移既有灵感图或作品集。回退旧镜像不需要删表，但旧版本无法处理交付数据；禁止直接删除新表来回滚含真实照片的任务。

| app_configs key | 初始值 | 含义 |
|---|---:|---|
| delivery.preview_bytes | 1000000 | 十进制预览体积上限，允许范围 10000—1000000 |
| delivery.preview_long_edge | 2560 | 预览最大长边，允许 320—4096 |
| delivery.max_photos | 2000 | 每任务全部底片和精修数量 |
| delivery.max_task_bytes | 21474836480 | 原件与预览总量，20GiB，不含临时 ZIP |
| delivery.export_retention_hours | 24 | 已结束临时包保留小时数，上限 720 |
| delivery.public_requests_per_minute | 360 | 每进程每 IP 每分钟公开请求数，上限 3600 |

以上均 orgid=-1、is_public=false、is_secret=false，由统一配置服务读取。上传单文件上限继续受 files.max_upload_bytes；存储类型从 files.active_store_type 按操作读取。压缩质量 76—92、4000 万像素安全上限和单解码槽属于算法/资源安全边界，不是对外承诺的摄影质量等级。

## 本批未实现或尚未验收范围

- 不包含多人独立席位、在线支付、AI 自动筛片、专业修图软件插件、项目/档期关联、任务模板、封面自选、并排比较及筛片撤销历史。
- 没有分片断点续传、上传队列跨刷新恢复或专门 RAW 解码；本地目录复制未提供跨平台桥接。客户单图精修备注已支持，但没有独立的售后修订工单和版本对比。
- 没有整任务物理删除/照片回收站和照片保留期自动删除；当前以暂停、取消、归档管理，原件长期保留，只有临时 ZIP 自动清理。
- 预览在上传请求内串行生成；未实现独立异步预览队列。容量上限之内的大规模 2000 张/20GiB 性能尚未进行压力测试。
- 未做真实相机样张的主观画质验收；合成高纹理测试验证体积、尺寸和原件保护，不能据此承诺原图级细节。
- Apple、PC 原生壳、微信小程序、真实 Android 设备内存/文件选择/热更新、真实公网访问码和二维码扫码、生产 webhook 网络投递均未验收。
- 不涉及官网、APK 分发地址及原生桥接改动，因此本批无需官网包或新 APK；共享页面提供 Web 和 Android 签名资源。发布和部署尚未执行。
