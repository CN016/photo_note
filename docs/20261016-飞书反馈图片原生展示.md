# 飞书反馈图片原生展示

## 目的

让新反馈通知在飞书中直接展示上传图片，同时保留没有飞书应用凭证时的现有公共图片链接通知。

## 主要改动

- 核对飞书开放平台的自定义机器人格式：官方自定义机器人富文本以 `img` 节点和图片上传返回的 `image_key` 展示原生图片；当前通知发送的卡片 Markdown 不会把 `![...](URL)` 转为该图片节点。
- 新增迁移 `backend/migrations/000014_seed_feishu_feedback_image_upload.sql`，增加默认留空、不可公开的 `feedback.feishu_app_id` 和 `feedback.feishu_app_secret`。
- 修订 `docs/backend-design-v1.md` 的配置表说明：应用密钥可以保存在私有 `app_configs` 项中，但公开配置仍禁止返回任何秘密。
- worker 从当前分段生成的 HTTPS 图片 URL 中解析末尾 storekey，并再次校验公共 key 标记与固定公共图片路由；这样已有的待重试通知也能上传图片，无需重写历史 outbox。worker 获取短期 tenant token，从公共图片存储读取图片后上传到飞书，再以 `post` 富文本的 `img` 节点发送；用户反馈文字作为普通文本节点发送，图片查看链接仍保留。
- 图片读取前校验公共 key 标记和实际类型；单张上传限制为 10 MiB。应用密钥、tenant token 和上传后的图片 key 不写入日志或站内消息响应。缺少两项凭证时继续发送原有可点击图片链接；凭证不完整、图片上传失败会留下可重试的安全投递状态。
- 消息中心增加对应投递错误码的中英文文案，避免将内部分类原样展示给用户。
- 后端版本从 `2.3.4` 升至 `2.3.5`，更新后端运维说明和 V1 接口设计记录。

## 验证

- `gofmt`：完成。
- `go build ./...`：通过。
- `pnpm run build`：通过；Vite 提示存在大于 500 KiB 的 chunk。
- 飞书通知中英文 JSON 键集合：一致。
- `git diff --check`：通过。
- 飞书官方自定义机器人指南确认 `post` 富文本图片节点需要 `image_key`，图片 key 由上传图片接口获取；上传图片要求应用启用机器人能力和图片资源权限。

## 未验证和限制

- 未运行测试或连接真实飞书租户；尚未配置应用凭证、`im:resource` 权限和线上 webhook，因此真实群聊中的图片展示仍需部署后验证。
- 启用原生图片前，运维需应用迁移 `000014`，填写私有 `feedback.feishu_app_id`、`feedback.feishu_app_secret`，并确保应用已开启机器人能力及图片资源上传权限。未配置时保持链接模式。
