# 灵感图条件筛选与高清图缓存优化

## 改动目的

将灵感图列表的条件入口改为顶部四个常驻图标，补齐色环明暗范围、快捷人数、备注和锚点文本检索、2:3 图片框、密集锚点展示以及高清详情图本地缓存，减少重复下载并保持列表与详情视觉一致。

## 主要内容

- 顶部固定展示色环、文本、标签和人数四个图标，点击后渲染对应条件；移除原筛选下拉图标。
- 色环使用二十四段完整色相谱和中心饱和度渐变，并增加纵向明度条，覆盖黑色、灰色、白色及全部明暗颜色。按住色环或明度条只更新放大预览，松开后才提交条件并检索；常驻黑白灰三个色块已移除。
- 人数默认提供“无人、1人、2人、3人、4人、5人、6人、多人”快捷按钮，“多人”映射 6 至 100000 人；可切换到原有有人/无人/精确/范围高级模式。
- `GET /api/v1/inspirations` 的 `q` 同时检索文件名、`data.image_note` 和 `data.anchors[].note`，并保持现有分页、租户与创建者隔离。
- 列表图片框固定为 2:3 并使用与详情一致的居中裁切；锚点映射旋转和裁切，锚点超过四个时只显示位置点。
- 列表先显示缩略预览，接近视口时按并发队列准备详情图，并通过透明度过渡到高清图。高清工作图写入 Cache Storage，使用服务端 `file_hash` 作为内容版本；版本变化时删除旧缓存后再获取新图，退出或切换空间时清除私有缓存。
- 后端版本递增为 `4.13.0`，Web 版本为 `5.2.0`，Web 发布号为 `1795334770527`。本批无数据库迁移。

## 验证方式及结果

- Web 单测：39 个文件、163 项全部通过；TypeScript 类型检查与生产构建通过；29 组中英文命名空间键一致。
- 后端：`go test ./...`、`go vet ./...` 通过；在独立临时 PostgreSQL 16 数据库执行全部迁移并运行 `TestInspirationLibraryPostgres`，文件名、整图备注和锚点文本真实检索通过。
- 浏览器：1440px 和 390px 验证四图标、色环、明度条、人数快捷/高级模式、2:3 卡片和密集锚点；浅色与深色模式均完成截图检查。
- 色环和明度条拖动期间未产生列表检索请求，松开后分别提交 `color` 条件；“多人”实际提交 `people_mode=range&people_min=6&people_max=100000`。
- 缓存写入 8 张高清工作图；页面重载后仅重新请求缩略图，高清详情文件全部由本地缓存复用。
- 工作区无障碍检查无 axe violation；仅保留背景渐变导致的 color-contrast incomplete 项供人工复核。

## 尚未验证或已知限制

- 未执行生产部署、线上真实图片数据验收或 Android/iOS 真机验收。
- “多人”按需求中的“6人以上”实现为大于等于 6 人，因此与“6人”精确按钮存在重叠；多人范围上限为现有服务端允许的 100000。
- 历史记录没有 `file_hash` 时使用更新时间作为兜底缓存版本，内容未变化但编辑锚点时可能多获取一次高清工作图。
- 本批未修改独立官网、PC 壳、iOS 壳和微信小程序专用代码。
