# 灵感图文件压缩与哈希

## 改动目的

为灵感图保留原始文件名和可用于内容查找的文件哈希；创建或提交图片 key 更新时，由后端读取 storekey 对应文件，必要时压缩并覆盖原文件，再根据最终内容生成哈希，避免信任客户端摘要并保持 key 稳定。

## 主要内容

- `inspirations` 新增 `file_name` 和可空 `file_hash` 字段；为非空哈希建立部分 B-tree 索引，并添加中文字段注释。
- 新增 `backend/migrations/000005_add_inspiration_file_metadata.sql`，不修改历史迁移；历史记录的文件名默认为空，哈希为空。
- 灵感图创建和更新接口接受可选 `file_name`。当 `image_key` 是有效 storekey 时，后端读取文件；超过 1 MB 的不透明图片压为 JPEG，含透明像素的图片缩小后保留为 PNG，并原位覆盖同一 key。最终实际文件字节用于计算 SHA-256；更新图片 key 会重算哈希，改为非 storekey 时清空旧哈希。
- 新增图片处理模块，支持 JPEG、PNG、静态 GIF 和 WebP；超过目标大小的动画 GIF/WebP 或超过 4000 万像素的图片会被拒绝。JPEG EXIF 方向会应用到像素后再编码，其他元数据不会复制。
- 文件存储新增同目录临时文件加原子重命名覆盖；文件下载根据实际内容推断 MIME 类型和扩展名，覆盖后保持原 storekey 可读。
- 新增 `golang.org/x/image v0.30.0`，用于 WebP 解码和高质量缩放；其 Go 版本要求与项目一致。
- 灵感图创建、详情、列表和更新响应均包含 `file_name` 与 `file_hash`；启动检查要求已应用新增迁移。

## 验证方式及结果

- `go build ./...` 成功；`git diff --check` 通过。
- `docker compose build api` 成功，API 容器重启后 `/healthz` 返回 `ok`。
- 在本地 PostgreSQL 17 和 Redis 上通过真实 HTTP 流程注册、上传、创建、更新、下载：6,485,612 字节的不透明 PNG 压到 997,798 字节 JPEG；5,604,818 字节的透明 PNG 压到 981,185 字节 PNG。原 storekey 保持不变，两次 `file_hash` 均与下载字节 SHA-256 一致；重复提交已压缩图片后哈希、长度和 MIME 类型不变。
- PostgreSQL 查询确认 `ix_inspirations_file_hash` 存在、项目 schema 外键数量为 0，验收用户清理后数量为 0；验收文件由脚本按生成路径清理。

## 尚未验证的内容或已知限制

- OSS storekey 的文件读取依赖 OSS 后端接入；当前 OSS 类型仍按既有行为返回未实现错误。
- 历史 OSS key 或其他非 storekey 图片标识无法由当前本地存储读取，因此历史哈希保持为空。
- 含透明像素的超大图片通过缩小尺寸达到 1 MB 目标，可能降低分辨率；超大动画 GIF/WebP 不会被扁平化，接口会返回校验错误。
