# 官网安卓测试包下载与部署准备

## 目的与范围

在独立官网提供本批 Android 9+ 内置 GeckoView 测试包下载，并明确官网、业务 Web、安卓包和后端各自的构建与部署关系。仅修改官网及文档，不改业务逻辑、后端或安卓应用，不执行生产部署。

## 主要改动

- 下载页新增独立安卓测试版区，显示 Android 9+、内置内核、版本、架构、大小、安装提示及 SHA-256。ARM64 标记为普通手机推荐；ARMv7 用于旧 32 位手机，x86_64 用于模拟器。保留其他平台的独立状态，不冒充正式发布或商店上架。
- `VITE_ANDROID_BUNDLED_DOWNLOADS=true` 启用同源静态托管，`VITE_ANDROID_ASSET_BASE` 配置下载基础路径，当前为 `/releases/android`。现有外部 HTTPS 正式下载配置继续保留。
- 官网构建读取安卓版本和真实 APK，对照对应 `.sha256` 校验源文件，复制进官网 `dist/releases/android/` 后再校验，生成 `release.json`。缺包或摘要不一致会停止构建；安装包和本地配置不提交 Git。
- 页面从统一配置模块读取经构建插件核验的发布数据，版本与大小不手工填写，地址使用对应静态文件的同源路径，不猜测尚不存在的公网地址。
- 提供 Nginx 下载配置示例：正确 APK MIME、校验文件类型、缺失包返回 404，禁止回退首页。预览服务器也按相同规则处理。
- 新增 `pnpm check:downloads <release.json 地址>`，流式校验三份完整下载的长度、MIME、SHA-256、校验文件和缺包 404。
- 补充双语文案、部署说明及协作规范，解释测试包与正式下载的切换方式。

## 实际验证

- 官网 `pnpm build` 通过，包含 TypeScript、中英文键集合、既有配置校验及 Vite 多页构建；三个 APK 与校验文件均写入 `website/dist/releases/android/`。
- `pnpm check:downloads http://127.0.0.1:4176/releases/android/release.json` 通过：三架构完整 HTTP 文件的 MIME、长度、摘要及校验文件均一致；不存在的 APK 返回 404。
- 使用 agent-browser 独立会话检查本地 `/download/`：桌面中文、英文切换、390px 手机布局与下载入口通过；390px 下文档宽度与视口均为 390，无横向溢出。截图仅用于本地验证，未提交或部署。
- 业务 Web 另外执行普通 `pnpm build` 通过，恢复默认浏览器目标构建，输出 `frontend/apps/web/dist/`；保留既有大 chunk 提示。没有以安卓专用构建替代普通 Web 发布构建。
- `git diff --check` 通过；未将 `.env`、APK、dist、node_modules 或截图加入提交。

## 下一步部署

1. 将 `frontend/apps/web/dist/` 全部内容部署到原业务 Web 静态目录，保留既有 API 反向代理；不要上传到官网目录。
2. 将 `website/dist/` 全部内容部署到官网 HTTPS 根目录，包括 `download/`、`assets/`、`licenses/`、`releases/`；下载页是 `/download/`。
3. 参考 `website/deploy/nginx-downloads.conf.example` 配置静态下载 MIME 与 404，确认站点默认文件为 `index.html`。
4. 有 CDN 时完整上传所有资源后再刷新页面缓存。检查首页、下载页、真实 APK 下载及摘要；可对生产 `release.json` 运行下载检查脚本。

本批构建产物已经准备好，无需用户再次在本机重复打包。官网仅新增下载入口，不改变 APK 内置内容，已有三份安卓测试包无需重打。后端无改动，不需要重建或重启。

## 限制

- 尚未连接官网或 Web 生产服务器，没有上传文件、修改远端 Nginx、刷新 CDN 或验证公网下载。官网正式域名未配置时仍不生成 canonical。
- 当前安卓产物仍为调试签名测试版；真实账号、ARM 真机等验收边界沿用安卓工程记录。官网可下载不代表这些验收已经完成。
- 开启随站托管模式后，后续官网构建依赖本机存在匹配版本的 APK 和摘要；在新机器/CI 需先构建安卓包，或关闭该模式。
