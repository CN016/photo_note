# 安卓签名资源动态更新与独立更新页

## 改动目的与范围

解决Web已发布而旧APK仍停留在内置页面的问题。安卓壳升级至1.1.0、安装版本4；共享Web保持单一代码来源，新增独立发布号、签名更新包及原生更新进度页面。后端代码、数据库和Compose未变，不重打API镜像。

Gecko官方内置扩展接口只能读取APK目录，不能直接装载下载目录。本批保留固定桥接扩展，通过只监听127.0.0.1的私有资源服务加载已验签Web包。来源端口固定，启动凭据仅放原生请求头、不出现在导航URL；Cookie、Host、Origin、扩展ID、会话及顶层检查共同限制访问。API流式转发到固定HTTPS地址，保留现有路径前缀和业务鉴权，不转发本机Cookie，不允许任意上游或重定向。

更新只在启动时进行，不打断编辑。包含签名、包和逐文件哈希校验，下载暂存、兼容性检查、45秒启动确认、失败/未确认重启回退、失败版本隔离和过期目录清理。原始APK基线保留。中英文原生更新页包含检查、下载百分比、校验、版本及失败重试状态；已查看实际Android 9模拟器截图。

首次从旧来源迁移本应用localStorage，后续资源更新保持来源。迁移失败时需要重新登录；本批没有使用真实账号验证迁移，不能承诺所有历史安装都能免登录。

## 发布与交付

用户指定使用现有业务Web域名下 `/android-updates/latest.json`，本机已通过环境配置接入。更新私钥保存于仓库外用户目录 `.photo-nini/keys/`，目录权限限制为当前用户；仓库和APK只包含公钥。私钥应另行安全备份，CI发布需配置同一私钥，不能用另一把钥匙重新签名。

`pnpm --dir frontend/apps/web build` 在本机自动生成 `web-release.json` 和 `dist/android-updates/`；未配置签名私钥的环境会明确跳过更新包，CI可用显式打包命令使配置缺失时失败。部署必须上传更新目录，先传版本ZIP、最后替换latest.json，并禁止SPA回退；详见 [发布说明](android-web-updates.md)。

交付位置：

- `frontend/apps/android/artifacts/photo-nini-1.1.0-{arm64-v8a,armeabi-v7a,x86_64}-debug.apk`，各自附SHA-256；这些是调试签名APK，尚未使用生产签名或进行商店分发。
- `backend/dist/photo-nini-web-20261027-android-updates.zip`：包含业务Web和更新目录的部署包，附SHA-256。
- `frontend/apps/web/dist/android-updates/`：约19.4MB的本次独立更新ZIP、签名清单及可读版本记录。APK不会再嵌套打入此ZIP。
- `backend/dist/android-update-delivery.json` 和 [结构化验收记录](benchmarks/20261027-android-web-updates.json)：版本、产物字节数、校验值与验证边界。

现有旧APK须先安装一次1.1.0。之后每次递增发布号、构建并部署Web及更新目录，兼容壳即可在下次启动更新页面资源；内核和原生协议更新仍需新APK。

## 实际验证及结果

- 共享Web：65项Vitest通过；`vue-tsc --noEmit && vite build`通过，含更新包postbuild生成。
- 发布脚本：2项Node测试通过，覆盖签名验证、篡改拒绝及路径边界。实际清单用APK公钥验签成功，实际ZIP的CRC和395个文件哈希全部一致。
- 安卓：`assembleDebug lintDebug assembleDebugAndroidTest`通过；生成三个ABI包，Lint 0错误、21项警告，主要涉及既有资源配置和样式建议，未声明零警告。
- Android 9/API28 x86_64模拟器：最终8项instrumentation全部通过。包括签名资源安装、哈希/签名篡改拒绝、目录越界拒绝、候选重启回退、显式回退、未授权本机请求拒绝、跨来源拒绝、启动Cookie、固定HTTPS代理、共享应用桥接、导出取消/保存/分享、4096² Canvas编码解码及相册选择。
- 增补代理POST上传检查后，重新执行更新专项2项通过：请求正文、鉴权头、`/backendApi`前缀正确，本机Cookie未发送上游。
- 首次模拟器回归被Pixel Launcher无响应弹窗干扰，后续关闭弹窗复测；Canvas测试原先只接受DocumentsUI，与既有图片相册行为不符，已修改为接受系统文件/照片选择器并通过。没有把失败的首轮当作验收通过。
- Web部署ZIP通过CRC，三份APK均核对启用更新的配置、基线发布号和API地址，确认不含嵌套更新ZIP；原生进度页已视觉检查。

## 未验证与限制

尚未部署生产更新目录；不能据本地构建声称用户手机已经更新。未覆盖实体Android设备、ARM运行、API36模拟器、真实账号完整业务、生产签名及商店政策验收。历史登录态迁移仅实现兼容路径，真实旧安装仍需验证。iOS、PC原生壳、微信小程序没有增加此更新机制。
