# 组织多租户隔离与管理（4.0.0）

## 行为与权限

注册和登录默认进入 `orgid=-1` 个人空间。账号全局唯一，一个账号可加入多个组织；加入组织不搬迁个人资料。普通业务同时按当前组织和创建者过滤，同组织成员也不能互看项目、计划、账本、档期、消息或 webhook。

平台管理员可创建、停启组织、维护管理员和成员；组织管理员可维护本组织名称、成员和灵感图库，图库编辑保留原创建者。组织管理员没有系统用户、配置和反馈权限。平台图库必须显式选择一个组织（含个人域），不能混查所有组织。最后一位有效组织管理员受事务保护。移除成员保留资料，重新加入恢复其原组织访问权限。

反馈与系统配置保持全局功能；反馈回复进入提交者个人消息中心。公开档期、游客预约、反馈图片保持原公开入口。完整接口与兼容约定见 [多租户接口说明](multitenancy-api-v1.md)。

## 数据与文件

迁移 `backend/migrations/000021_multitenant_organizations.sql` 为原 20 表增加 `orgid`，新增组织、成员和私有文件授权表，共 23 表。历史数据留在个人域，组织编号使用独立正整数业务序列，所有新字段有中文注释，不创建外键。

私有业务索引与业务唯一约束包含组织维度，upsert 冲突目标同步调整。全局主键、业务 UUID、手机号和公开令牌仍保持全局唯一；GIN 和跨组织 worker 调度索引保留，另加组织过滤索引。账号、系统配置、反馈及反馈通知任务强制 `orgid=-1`。

GORM 查询、更新、删除和创建使用默认拒绝的组织回调；缺少可信租户上下文报错，禁止更新资源所属组织。原始 SQL、关联和聚合显式带组织条件。后台队列扫描使用专用系统上下文，处理时从持久化记录恢复原组织与创建者；外发前复查组织、成员及通知渠道。

私有文件上传、读取、引用、替换与删除统一检查 `file_ownerships`。历史头像、灵感图、计划和项目封面、附件按引用回填，保留物理 key；多账号共用同一 key 的冲突记录拒绝访问，孤立文件不会自动授权。管理图库读取也只能访问指定图片实际引用的文件。头像使用独立的本人接口，验证实际图片内容。

## Web 与会话

新增空间切换和组织管理页面，以及组织图库查看、编辑、删除入口。中英文文案配对。令牌包含组织、会话 UUID 与空间版本；Redis 原子刷新、切换、撤销，旧版会话要求重新登录。服务端每次请求重新确认成员与组织状态。

浏览器通过 BroadcastChannel、Web Locks 和会话版本协调所有标签页：先保存旧空间、等待上传和请求结束，再切换凭证。未完成手动表单会取消切换；图片编辑器可保存已有图片后退出。请求在重试及读取响应后再次确认版本，迟到响应不能进入新空间。结果不确定或协调页异常消失时清理会话，避免继续使用未知状态凭证。

实际双标签页测试发现页面退出动画会延迟旧编辑器卸载，现已移除该路由动画并等待空间页挂载；同时修复屏障锁释放及终态后重新加入的竞态。连续切换后两个标签页均重新持有 shared 锁。BFCache 恢复页面重新加载，避免旧表单套用新空间。

## 升级顺序与限制

1. 备份数据库、文件存储及 Redis 会话状态，先在副本执行迁移并核对历史文件冲突。
2. 停止旧版 API 和 worker，执行尚未应用的迁移。该迁移包含事务及索引重建，应安排维护窗口。
3. 同步发布 4.0.0 前后端，启动检查通过后重新登录，再验证组织成员、私有文件和后台任务。
4. 出现组织数据后不能直接退回不识别组织的旧版；回退需要协调代码、数据库、文件和会话备份，不能只回退二进制。

本次仅完成本地实现与验证，未推送、未部署、未修改生产数据库。外部渠道已发送的消息无法撤回；未在真实对象存储、真实 webhook 或移动设备上验收。
