# 灵感图图片属性元数据

## 改动目的

灵感图在压缩前采集原始图片中可识别的属性，保存图片基础信息、Windows 属性页常见的描述与拍摄字段，以及 EXIF、IPTC、XMP 等其他带命名空间的标签。文件系统创建时间、访问时间、本机路径和权限不作为图片元数据保存。

## 主要改动

- 新增 `backend/migrations/000016_add_inspiration_image_metadata.sql`，为灵感图增加 56 个可空属性列和 `image_metadata_extra` JSONB（共 57 列）。每个新增列均有中文说明，没有外键。原始图片字节数单独保存在 `source_file_size`；现有 `file_size` 继续代表压缩工作副本大小。曝光、分辨率、距离、GPS、闪光灯能量等数值按固定单位保存。
- Web 在画布解码和转换前通过动态加载的 `exifr` 读取原文件属性，并记录 `File.size` 与 `File.lastModified`。解析器不支持格式、无属性或读取失败时，仍保存浏览器可读的原图大小和修改时间。扩展标签限制为 1 MiB。
- 创建请求和换图 PATCH 接受顶层 `image_metadata`。详情、创建及更新响应返回完整属性；列表省略该对象。详情页以只读分组显示非空属性，并提供可展开的其他标签，中英文键集合保持一致。
- 后端 Docker 运行镜像安装 ExifTool。后台任务优先读取 `data.source_image_key`，不可读时回退到本次 `image_key`，在压缩前解析并按图片 key 和异步代次写入。服务端有值时覆盖同名客户端值；服务端缺失的值保留。并发的元数据更新不会被后台缺失字段覆盖，扩展标签按 JSONB 原子合并。解析失败时继续压缩。
- ExifTool 的文件系统时间、权限等属性被过滤；路径、GPS 和设备序列号不会写入日志或通知。历史灵感图不回填。基于当前 `2.5.0` 版本递增为 `2.6.0`，接口设计、后端说明和第三方许可记录已更新。

## 验证

- `go test ./...`：通过。
- `go vet ./...`：通过。
- `pnpm test`：6 个测试文件、21 项测试全部通过，覆盖属性映射、原图大小和修改时间、无元数据、读取失败、GPS 缺失、扩展标签上限，以及创建/换图/详情/列表 API 行为。
- `pnpm build`：通过。构建仍提示现有 HEIC WASM bundle 约 2.04 MB，超过 Vite 的 500 KB 提示阈值。
- `docker build -f Dockerfile -t photo-nini-api:metadata-check .`：通过；镜像内 ExifTool 版本为 13.30。通过 Docker 标准输入读取所附属性截图 PNG，ExifTool 返回 JSON 并识别出 356 × 554 像素。
- 静态核对迁移：57 个新增列均存在模型映射及中文列注释，未发现外键声明。中英文详情命名空间各 137 个键，键集合一致且没有重复键。

## 未验证内容与限制

- 没有在 PostgreSQL 实例执行迁移；部署时需按顺序应用此前迁移和 `000016`。本次没有进行真实数据库端到端持久化测试。
- 所附图片是属性页截图，不是截图中显示属性的原始照片；图片格式、编码器与元数据写入方式会影响实际可读取字段。此功能尽力读取跨平台图片标签，不能保证与每台 Windows 设备的属性页完全一致。
- 浏览器单测通过模拟解析器标签验证 EXIF/IPTC/XMP 映射；没有在 Windows 桌面壳、Android、iOS 或微信小程序中分别进行运行验证。
- 前端构建、详情页展示与语言资源通过类型检查和构建验证；本次没有进行浏览器交互式视觉验收。
