# 灵感库缩略图缓存与识别触发收紧（4.2.1）

## 目的与改动

解决日历和列表重复下载原图、浏览器重复缩放编码导致的加载缓慢。服务器生成最长边384像素的持久化JPEG显示副本，保持原图不变；压缩后预生成，历史图片首次读取时补生成。缓存命中仍检查文件归属；换图和删除同步清理副本。生成并发最多2，限制解码像素数，损坏或超限图片不绕过限制。

前端日历与列表共用按文件内容版本区分的Blob缓存，合并相同请求、下载并发4，最多48项/16MiB、有效期5分钟。空间切换和退出清理缓存，迟到响应不能写入新空间。中英文处理规则提示同步补齐。

AI仅在新增后的异步任务及每日未识别扫描进入队列。服务启动不补扫，浏览接口不触发AI，已成功识别的数据不因算法版本变化重跑。换图立即压缩、清除旧识别结果，等待每日扫描；兼容重试接口返回409，移除手动识别按钮。队列内部仍保留有限失败重试与租约恢复。增加Python就绪检测，防止冷启动时领取任务却连接失败；Unix Socket连接积压上限调整为32，推理并发仍最多10。

## 升级方式

后端版本4.2.1。备份后执行 `backend/migrations/000024_inspiration_thumbnail_triggers.sql`，再升级API及Web。新增私有配置 `files.thumbnails` 和任务准入字段 `analysis_ready`；迁移前已有任务默认等待每日扫描授权。Compose不变，保留Alpine及已编译AI基础镜像，无需重编译ONNX Runtime。

API镜像 `photo-nini-api:4.2.1` 同时标记为 `photo-nini-api:local`，镜像ID为 `7be8590bfbfe552b0feeeec13efe918add82da272b48b83b33d3cbcf36825579`。交付文件位于 `backend/dist/`，gzip可直接通过 `docker load --input` 导入；校验值见同名 `.sha256` 和交付清单。

## 实际验证

- 独立PostgreSQL测试库执行完整Go测试通过，覆盖迁移、队列准入、空间隔离、缓存授权、换图和清理；前端65项测试、生产构建及中英文键一致性通过。
- Chromium验证日历和列表10张图片只发出10个独立缩略图请求；页面内切走返回新增下载0次，桌面及390像素宽手机布局截图留存。
- 10张图传输量由1,906,182字节降至268,471字节。历史大图925,003字节生成20,043字节副本，首次296.27ms、缓存读取20.28ms；这些是本机测试数据。
- 实际替换图片后，多次浏览及重启均未触发AI；受控每日扫描后成功识别，每日存图计数保持不变。跨用户读取已缓存副本被拒绝。
- 最终API容器限制2核、2GiB，10个已就绪识别任务同时执行，5轮均完成并保存结果，最慢2.669秒，不包含上传和压缩。容器记录峰值内存306,552,832字节。
- API gzip解压哈希与原始tar一致，压缩包Docker回载成功；Web ZIP CRC检查通过。结构化证据见 [验收数据](benchmarks/20261027-inspiration-thumbnails-v421.json)。

## 限制

本批未部署生产环境；源图片缺失或文件归属异常产生的404不能由缓存恢复。历史HEIC/AVIF保留客户端兼容处理，未新增特殊格式真机验收。PC原生壳、Android/iOS及微信小程序未实机验证。
