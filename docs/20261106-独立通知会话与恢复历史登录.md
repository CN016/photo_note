# 独立通知会话与恢复历史登录

## 目的与历史证据

对照 `eebd3be` 的原生持久凭据与 HTTP 恢复路径，以及 `7bb41c3`、`3e302c8` 引入的通知共享刷新和恢复逻辑。1.3.x 将 Web 登录改经通知认证桥接，并把 HTTP 鉴权代理与后台网络刷新放在同一凭据锁内；通知网络等待可阻塞页面恢复，两个调用端也不能分别管理单次刷新令牌。本批移除这条耦合路径，不再叠加启动等待。

后端原本允许多个独立登录，并非整个账号只能有一个 token。继续保留单次刷新令牌轮换，新增独立、受限通知会话；不通过复用已消费的刷新令牌掩盖并发问题。

## 主要修改

- Web 恢复历史 `/api/v1/auth/refresh` HTTP 自动登录，随后读取 `/users/me`。这条链路不探测、不调用、不等待通知桥接。
- Android 本机 HTTP 代理恢复独立 Web SessionVault，沿用 `session-vault-v1.json` 和原 Keystore 别名；移除通知共享锁、替换网页 token 和认证桥接。
- 页面已有用户后异步签发通知 token，经独立通知桥接保存。通知使用 `notice-session-v1.json`、独立 Keystore 别名、独立初始化执行器和轮询工作线程；后台服务只刷新通知 token。
- 通知签发 401/403/超时不触发 Web 刷新或清凭据；不计入业务请求排空队列，空间切换不等通知网络。迟到响应必须匹配原 Web session_id/orgid/session_version。
- 通知初始化同代次合并；失败可在前台焦点或正常会话更新时重试。登录不等待初始化；拒绝系统通知权限不影响业务。
- 每次进入 APK 的异步版本检测保留。更新弹窗仪器测试使用独立状态和合成版本，避免真实官网检查覆盖夹具。

## 新接口与安全范围

`POST /api/v1/auth/notification-session` 使用当前 Web Access Token，无请求体，成功返回既有 `{data:{tokens:TokenPair}}`。后端只使用认证上下文，不接收用户、空间和用途参数。

每个 Web 会话最多一个通知子会话；重复签发原子撤销旧通知会话，不修改 Web 访问/刷新 token。普通登录、通知会话的 session_id、令牌和 Redis 索引独立。通知令牌只允许 GET `/api/v1/notifications`、GET `/api/v1/notifications/unread-count`、POST `/api/v1/auth/logout`，刷新仍经原公开 `/auth/refresh` 校验刷新凭据。强制和可选鉴权入口都执行用途限制；通知不得切换空间或再创建通知会话。

子会话验证同时检查父 Web 会话的用户、空间、代次与有效性。Web 普通刷新不改变代次；Web 退出/切换空间会撤销旧通知访问能力。通知退出不撤销 Web，其他设备登录仍独立。无需迁移或删除既有 Web 凭据；已被旧版轮换撤销的 token 需重新登录一次。

## 版本与部署

- API 4.10.0；无新增数据库结构或 SQL 迁移，沿用已部署版本所需既有迁移。
- Android 1.4.0 / versionCode 11；本批为 debug 签名，三 ABI 包含同一 Web 构建。
- 签名 Web 更新 `minShellCode=11`，阻止 HTTP 独立会话页面进入仍共享凭据的 1.3.x 壳；修复必须安装新版 APK。
- 顺序：先升级 API，再部署业务 Web 的完整 `android-updates/`，部署独立官网新 APK 与 release.json；用户覆盖安装 1.4.0。APK 原生改动无法仅热更新完成。
- PC/普通浏览器复用 HTTP 恢复；iOS/微信小程序无新原生接口调用，不构建其安装包。

## 验证结果与边界

- `go test ./...` 通过；新增通知会话测试使用独立 Redis 容器，验证双方各 8 次并发刷新、重签发、通知退出、Web 退出、多个 Web 登录、跨空间及越权隔离。未连接生产 Redis 或数据库；未配置的 PostgreSQL 集成测试不视为数据库验收。
- Web 全量 23 文件 / 98 测试通过，覆盖通知桥接不返回时 HTTP 自动恢复、通知失败不清 Web、通知请求不阻塞业务排空及迟到响应隔离。
- 实际生产 Web 构建通过，RSA 签名资源包生成。浏览器加载构建产物，通过实际本地 HTTP 接口刷新和读取用户；通知桥接一直不返回仍进入消息中心。此为合成账号/接口，不是线上登录验收。
- Android APK/Lint 通过；Android 9 模拟器 12 项相关仪器测试全部通过（凭据、通知、更新检测）；首次更新弹窗夹具被真实检查覆盖，隔离测试状态后全项重跑通过。凭据独立锁测试主动持有通知锁，Web bootstrap 仍可完成；轮换/退出通知不改写 Web 文件。额外手动两次仪器进程之间 force-stop 后，读取加密凭据恢复测试通过。
- 后台监听仍受 Doze、省电、强停、厂商策略及 Android dataSync 时限约束；不承诺永久常驻或严格轮询时效。
- 未完成真实账号、ARM 真机、Android 13+ 权限及现代系统后台限制验收；不以模拟器或单元测试代替以上验收。未部署线上、未推送远端。
