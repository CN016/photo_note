# 灵感图异步压缩后清理原图

## 改动目的

压缩任务完成后不再通过站内消息或 webhook 通知用户，并回收编辑器单独上传的原始文件，避免同一张灵感图长期占用两份存储。

## 改动范围

- 移除灵感图压缩成功/失败时创建站内消息和 webhook outbox 的发布链路；压缩失败仍记录后台错误。
- 压缩和文件哈希/大小写回成功后，按 `image_key`、`async_version` 和当前原图 key 条件清理 `data.source_image_key`。确认其他灵感图未引用原图 key 后才删除文件；删除失败时保留原图引用并记录后台错误。
- 编辑器详情与图库缩略图改为使用压缩工作图 `image_key`。普通数据更新不能把服务端已清理的旧原图 key 写回；显式换图仍可提交新原图 key。
- 后端版本由 `2.7.0` 递增至 `2.7.1`。未修改 API 或数据库结构，不需要数据库迁移。

## 验证

- `gofmt`：本次修改的 Go 文件已格式化。
- `go build ./...`（目录：`backend/`）：通过。
- `npm run build`（目录：`frontend/apps/web/`）：通过；Vite 对超过 500 KiB 的 WASM 分块给出体积提示。
- `git diff --check`：通过。

## 未验证内容与限制

- 未连接 PostgreSQL 和真实文件存储验证异步删除及并发引用检查。
- 当前进程内队列不持久化；异常退出仍可能丢失未完成的压缩或清理任务。
