# 用户反馈通知与公共图片链接

## 改动目的

新反馈保存后可靠地创建后台通知任务；任务按独立私有配置查找已有接收用户，并将完整反馈内容送入站内消息及该用户启用的 webhook 渠道。反馈图片可由 webhook 和消息中心直接读取，不改变普通文件的鉴权边界，也不接入短信。

## 主要改动

- `feedbacks` 记录与 `feedback_notification_jobs` 任务在同一 PostgreSQL 事务中写入。worker 通过行锁和 `SKIP LOCKED` 领取任务，超过两分钟的处理中任务可恢复；临时错误使用退避重试，最多处理五次。稳定事件键 `feedback.submitted:<feedback business_id>` 使任务恢复时不会重复创建站内消息或 webhook outbox。
- 新增私有配置 `feedback.notify_admin`（默认 `false`）、`feedback.admin_phone` 和 `http.public_base_url`。开关关闭时任务安全标记为跳过；开启时手机号必须对应已有账户，公共地址必须是 HTTPS 且可包含反向代理路径前缀（如 `https://photo.016imcn.love/back`），不含查询参数、片段或凭据。无匹配用户或配置无效只记录安全错误分类，反馈仍保留。
- 反馈上传使用 `public_` key，并写入与普通文件分离的 `public/` 目录。新增无需鉴权的 `GET /api/v1/public-feedback-images/{storekey}`，只接受该公共 key 和实际 MIME 为 JPEG、PNG、GIF 或 WebP 的文件；给私有 key 添加标记不能定位原文件。
- 新增 `feedback.submitted` 事件，站内载荷包含完整纯文本、经过转义的 Markdown 和公共图片 URL。图片绝对 URL 由 `http.public_base_url` 生成，不采信请求 Host；消息中心以纯文本显示正文并内嵌展示图片。
- 每个启用 webhook 配置都为通知 Markdown 的每个分段创建独立 outbox。分段使用 3800 字节上限，保留 UTF-8 字符及完整图片引用，每段独立显示和重试。企业微信与钉钉发送 Markdown；飞书使用带 Markdown 元素的 interactive 卡片格式。
- 新增迁移 `backend/migrations/000013_feedback_notifications.sql`，为每张新表及字段添加中文说明，不创建外键；迁移还为 `notice_deliveries` 增加分段序号。后端版本从 `2.3.2` 升至 `2.3.3`。

## API 与运维配置

- 游客及已登录用户均可使用现有 `POST /api/v1/feedback` 提交反馈；成功响应仍为 `received: true`。
- 图片链接通过无需 token 的 `GET /api/v1/public-feedback-images/{storekey}` 读取。普通文件仍使用已鉴权的 `GET /api/v1/files/{storekey}`。
- 新数据库或现有数据库升级前先备份，并按顺序应用尚未执行的迁移，直至 `000013_feedback_notifications.sql`。服务不会自动运行迁移。
- 运维先设置 `feedback.admin_phone` 和 `http.public_base_url`，确认 HTTPS 地址及可选路径前缀能从外部读取后，再将 `feedback.notify_admin` 设为 `true`。手机号和域名不写入仓库示例、日志或反馈通知任务。
