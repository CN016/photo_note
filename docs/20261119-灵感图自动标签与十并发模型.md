# 灵感图自动标签与十并发模型

## 改动目的

灵感图上传后自动完成图片识别并尽可能多地打标签；每晚补齐数据库中尚无自动标签的历史图片。在 2GB 内存服务器上支持 10 个模型推理同时执行，并将新增模型、标签向量、运行依赖和许可文件打入 API Docker 镜像。

## 模型选型

- RAM++ 官方模型面向通用开放词表图片标签，覆盖能力强，但完整权重约 769MB，对当前 2GB CPU 容器偏重。
- MobileCLIP2-S0 参数更小，但模型采用 Apple ML Research Model TOU，商用发布边界不如 Apache-2.0 清晰。
- 最终选择 SigLIP 2 Base patch16-224。基础模型为 Apache-2.0，86M 参数；运行时使用 186,039,516 字节 FP16 视觉编码器，文本编码器只在构建前生成固定标签向量。
- 当前自编译 ONNX Runtime 缺少 INT8 模型所需的 `ConvInteger`，Q4F16 模型还依赖未注册的 `MatMulNBits`；两者均实测无法加载，因此没有为了文件更小而发布启动失败的方案。

参考来源：

- [RAM++ 官方仓库](https://github.com/xinyu1205/recognize-anything)
- [Apple MobileCLIP2 官方仓库](https://github.com/apple-aiml-research/ml-mobileclip)
- [SigLIP 2 模型卡](https://huggingface.co/google/siglip2-base-patch16-224)

## 主要实现

- `inspirations` 新增 `auto_tags jsonb`。成功结果保存模型版本、标签名称、来源、分数和完成时间；`NULL` 表示尚未完成自动标签。用户手工标签仍保存在 `tag_ids`。
- 上传成功继续复用现有持久化 `inspiration_processing_jobs`，压缩完成后在执行人物/颜色识别时同时生成自动标签；不需要第二套队列。
- AI 返回场景、物体、色彩、光线、构图、风格、氛围等模型标签，并补充人数、空镜、横竖构图、主色、明暗和饱和度等确定性标签。候选标签共 127 个，包含大远景、远景、全景、中景、中近景、近景、特写、大特写、半身、全身、胸像和过肩镜头等景别/构图术语。
- 自动标签会复用或创建当前空间、当前用户的标签，再与现有 `tag_ids` 求并集；不会清空或整体替换手工标签。单图最多接受 30 个标签，常规输出约 24 个。
- 每晚 `03:00` 的既有任务改为扫描 `analysis_status <> 'succeeded' OR auto_tags IS NULL` 的图片；每批 500 张、内部 ID 游标，只补齐未完成项。
- 旧图片仅补标签时若识别失败或等待重试，不降级既有 `analysis_status=succeeded` 和原人物/颜色画像。
- 模型进程保持单个共享 ONNX Session，10 个 HTTP 推理任务可同时进入模型调用；每个 ORT Session 单线程。请求正文总预算 256MB、解码像素预算 384MB，避免大图上传和十任务并发放大内存。
- API 版本从 `4.10.0` 增至 `4.11.0`。

## Docker 与模型资产

- 新增 `backend/ai/prepare_tag_embeddings.py`，下载约定 ONNX/tokenizer、校验 SHA-256、预计算 127 个标签向量。
- 最终 API 镜像包含 `siglip2_vision_fp16.onnx`、`siglip2_tag_embeddings.npz`、SigLIP2 来源说明和 Apache-2.0 许可。
- 视觉模型不提交 Git；标签向量约 0.36MB，作为可复现构建资产提交。`backend/ai/models/README.md` 记录来源和固定摘要。
- 镜像标签包含 `photo-nini.ai.tagger=siglip2-base-patch16-224-fp16` 与 `photo-nini.ai.tag-concurrency=10`。

## 验证方式及结果

- `go test ./...`：后端全部通过。
- Python AI 单元测试：通过，覆盖真实 YOLOX、SigLIP 和标签向量加载，验证空镜、横构图、白色、明亮、低饱和等确定性标签。
- 独立 PostgreSQL 17 容器：完整迁移测试与 `000022` 到 `000023/000024/000030` 增量迁移测试通过；验证自动标签写入、用户标签合并、字段中文注释和无外键。
- 最终 `photo-nini-api:4.11.0` 镜像构建通过；镜像内视觉模型 SHA-256 与来源记录一致，标签向量和 Apache-2.0 许可存在。
- 最终镜像在 Docker `--memory=2g --cpus=2` 下执行 10 个模型推理同时运行，实际最大推理重叠数为 10：10 张图约 14.20 秒，Python 进程峰值 RSS 约 1.228GB，单图 24 个标签。
- 390×844 前端验证沿用上一批详情页验证，本批后端新增未改变既有 `tag_ids/tag_names` 响应结构。

## 尚未验证与限制

- 2GB 全机还需要同时运行 Go API、PostgreSQL、Redis 和宿主系统；1.228GB 是 AI Python 进程峰值，不是整机峰值。低内存环境上线前应使用实际业务图片和实际 Compose 组合做持续运行压测。
- 标签准确率只用典型照片和确定性边界验证；复杂夜景、文字图、长尾主体和中文语义仍需用真实灵感库抽样评估。
- 当前没有手动重跑自动标签的 API；“未识别记录等待每日扫描”的既有 409 约定保持不变。
- 未在 ARM64、Windows 原生 AI 进程或其他 ONNX Runtime 版本上验证；模型工作流只对 Linux amd64 正式镜像给出结论。
