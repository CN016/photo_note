# 灵感库色相优先匹配

## 改动目的

修正绿色色环筛选时蓝色图片排在绿色图片前的问题。旧算法以加权 RGB 欧氏距离计算相似度，高饱和异色仍会得到较高分数，无法表达“查找相近主色”的预期。

## 主要内容或涉及范围

- 后端颜色匹配改为 HSV 色相主导评分：查询色和代表色色相差超过 60° 时不再贡献分数，避免绿、蓝等明显不同色相互相占据前排。
- 同色相颜色继续按饱和度、明度的接近程度修正，并乘以代表色在全图中的占比；同色深浅和浅色主体仍可匹配，低饱和颜色不再冒充彩色。
- 黑、白、灰查询改用明度接近度和低饱和程度评分，保持中性色筛选语义。
- 既有 `color_palette` 画像直接参与新评分，不需重算 AI 分析或新增数据库迁移。
- 后端版本从 `4.13.1` 提升到 `4.13.2`。

## 验证方式及结果

- 在临时隔离 PostgreSQL 17 容器中按版本顺序执行全部 30 个迁移，未使用生产数据库。
- `go test -p 1 ./... -count=1`：全部后端包通过。
- PostgreSQL 集成测试新增绿色主体高占比样本，并断言 `#00a651` 查询时绿色图片排第一、蓝色主体图片只排在后面；原有蓝色占比和中性色匹配断言继续通过。
- 真实集成测试同时发现并修正一处过期历史计数期望：删除图片按设计不回减，当前样本应保留 7 条历史存图记录。

## 尚未验证或已知限制

- 未在生产规模画像上做排序耗时基准；每个画像只遍历最多五个代表色，预期查询开销受控，但数据库环境差异仍需上线观测。
- 色相 60° 边界外的颜色完全不贡献分数；这符合颜色筛选语义，但渐变跨越多个色系的图片会以落入容差范围的代表色占比排序。
